# sim/ — 模拟盘脚本交接区（黑白机共用）

> 目录性质：**纯 JS / node 可跑 / 无第三方依赖**的成品模拟脚本，**入库共享**——这是 AGENTS.md"纯文档仓只放文档"的唯一例外（院长 2026-11-12 令："让每一次的成品脚本能够交接，黑白机都要有模拟操作"）。
> 纪律：`tmp/` 仍放过程件（不入库）；`sim/` 只放**可复跑的成品脚本**，每次跑完必须能独立复现报告数字。

## 一、目录与命名

```
sim/
  README.md              ← 本文件
  v22/
    core.js              ← 白机版 v22 全量核心盘（人口/粮/消费/财政/军费五账）
    full-*.js            ← 黑机版全量盘交接位（60+ 建筑/AI 决策器/科技/战争）
  v<n>/                  ← 后续版本同构
```

- 命名：`v<版本>-<主题>.js`（如 `v22-core.js` 简化为 `v22/core.js`）；参数集中在文件顶部 `PARAMS`。
- 输出：报告数字写回 `docs/06-设计/00-总纲/全量模拟-<版本>-<主题>.md`；原始 stdout 可存 `tmp/`（不入库）。

## 二、交接规则

1. **黑机**：每次全量盘跑完，把**成品脚本**提交到 `sim/v<n>/`（不要只贴报告）；报告里注明"脚本=sim/v<n>/xxx.js"。
2. **白机**：`pull` 后即可 `node sim/v<n>/xxx.js` 复跑；白机自写的盘也提交到这里。
3. **版本对齐**：脚本顶部注明所依据的文档版本（如"v22：数值尺度 S=8 + 生育率公式 + K_desire"）；文档改口径 → 脚本必须跟进。
4. **禁止**：脚本里内联魔法数（参数进 PARAMS）；依赖 Unity/本地资产；引用 tmp/ 路径。

## 三、v22 口径（当前有效）

| 项 | 口径 |
|---|---|
| 数值尺度 | 全局 ×8（人口/岗位/产出/造价/维护/单座上限/服务人口/粮/兵员/矿产） |
| 人口 | 单一式（人算 §7.2，2026-11-13 限速）：`g=0.006×h×f_L^1.5×f_F×(1.5−r)`、`ΔP=P×clamp(g,−2%,+2%)`；承载=舒适容量，可超载至 ~2 倍 |
| 消费池 | `民用人口/1000×2.5×K_desire×8`；份额 60/25/15；缺类/剩余回流 |
| K_desire | `clamp(1+0.3(在岗率−0.95)+0.2(宜居−50)/50−0.15交战−0.10军管−0.20税负−0.15供给危机, 0.5, 1.5)` |
| 军源 | 服役率 0.5~10%；军饷 0.05 财/兵/回；**B1：1 批=8,000 兵，轻兵 1 回合/批、重兵 2 回合/批；兵工厂 Lv1=1 条产线** |
| 资源 | 铁/煤/油国家级池（首版简化；油按 B1 §五）；库存上限 5 回合收入 |
| 粮 | 全国池；农田 320 粮/回；需求 P/1000 + 服役×1.5/1000 |
| 税 | Σ(800 + P/1500) |
| 科技 | 学院链 Lv1/2/3 = 10/16/24（每城 1 条链、开局每城一座学校）；入池 ÷800；**科技 40/40 后 60 回合终极工程 = 科技胜利** |
| 外交票制 | **弃权不算同意**，同意严格过半（5→3/4→3/3→2/2→2）；战争制裁全员参与、经济/裁军同意+弃权参与（[外交提案与表决](../docs/06-设计/05-外交/外交提案与表决.md)） |

运行：
- 标准全量盘：`node sim/v22/full.js 200 <seed>`
- 战时压力盘：`node sim/v22/full.js 200 <seed> stress <服役率>`（如 `stress 0.02`；强制全阵营交战、跳过外交）
