## 三、维护规则（写进每次收尾）

1. **裁定即同步**：每次院长裁定后，若涉及**游戏概念**→更新对应词条；若涉及**公式/常数**→更新 06-设计/00-总纲/索引-参数（开发检索）；若涉及**设计变更**→索引-决策（开发检索）。
2. **不双写正文**：词条写"是什么/怎么玩"，公式细节与参数出处留在开发检索与权威文档；冲突时**以权威文档为准**并在词条标注"⚠️ 已过期，见权威源"。
3. **同步日期必填 + 机器校验（2026-11-24 院长第 2 条：光有纪律必漂移）**：每个词条顶部 `syncDate` 必填；**收尾必跑 `node sim/tools/doc-sync.js stale`**——非空即有词条落后于其上游，须回写并刷新 syncDate 到 0 条。判定模型=词条 syncDate vs 头部引用上游的 git 最后提交日（不靠人判断）。台账见 [docs/meta/docs-index.json](../meta/docs-index.json)。
4. **术语**：新概念首现必须进 [术语表](../06-设计/00-总纲/术语表.md)。
5. **游戏内嵌**：黑机生成器 `tools/wiki/build_wiki.py` 可把本目录渲染成静态站（预览）与 JSON 索引（游戏内嵌数据源预研）；词条内容按"玩家视角"写即零改动可入游戏。

## 五、数据源生成与游戏内展示（院长 2026-11-24 第 3 条）

> **百科的最终形态是游戏内嵌数据源**，不是网站。HTML 站只是**白机权宜**（白机无 Unity，只能通过 HTML 间接读取百科内容）。

### 5.1 生成方向：从数据源提取，不手抄

| 内容 | 来源 | 生成方式 |
|---|---|---|
| **数值段**（卡数值/参数/公式系数） | `sim/data/cards.js`、`Assets/_Project/Data/*.json`、索引-参数表 | **由数据源渲染**——数据改→词条自动跟随，消除手抄漂移 |
| **概念说明**（是什么/怎么玩/常见疑问） | 人工撰写（玩家视角） | 人写，随设计定稿更新 |
| **状态元信息**（version/syncDate/stale） | `docs/meta/docs-index.json` | `doc-sync.js gen` 生成 |

- 现状：百科 100% 手写（数值也手抄）→ 漂移的根源。目标：**数值段自动化，只留概念文本给人**。
- 黑机 `tools/wiki/build_wiki.py` 已有雏形（渲染静态站 + JSON 索引），待扩展为"数据源→词条数值段"。
- **纪律**：手写数值只允许出现在"设计文档"里；百科数值一律标来源并可被脚本覆盖。

### 5.2 游戏内展示 ≠ 百科页面（需额外 UI 设计）

游戏里**不能照搬百科的"词条网页"形态**——玩家在游戏内需要的是**就地可用的信息**，不是读说明书：

| 场景 | 百科（当前） | 游戏内应有形态（待设计） |
|---|---|---|
| 政策卡数值 | 词条里一张长表 | 卡面直接显示（描述 + 小字数值），政策面板可对比 |
| 公式/系数 | 词条公式块 | 不展示公式；只在 tooltip 给"影响哪个数值、多少" |
| 决策史/设计理由 | 词条"决策史"表 | **完全不进游戏**（开发视角） |
| 系统总览 | 词条全文 | 首局教学 + 内嵌图鉴（分页、可搜索、带图标） |
| 状态/版本 | syncDate 元信息 | 不展示（玩家不关心） |

- → **百科是"事实库"，游戏内是"呈现层"**：同一份结构化数据，两套 UI。UI 形态待 UI 专题/院长手绘稿（挂账）。
- 白机 HTML 站的作用：①预览百科内容 ②给院长在无 Unity 环境下审阅 ③未来若做游戏内图鉴，可作为设计参考。
