## 三、每类接入的步骤（黑机执行清单）

1. 读该系统的定稿文档（见 [建筑目录清理单 §九](../06-设计/03-内政/建筑目录清理单.md) 表格"文档状态"列）。
2. `buildings.json`：`status: draft → active`；补 `outputs`/`jobs`/`power`/`livability` 等字段（按文档）。
3. Unity：`CitySettlement`/`ConstructionSystem`/对应系统（文化池/消费池/工业）读取新卡；**先加单元测试/断言**再翻正。
4. 回归：`dotnet build` 0/0 → BatchSmoke → BatchBuildTest → BatchSimulation 200 回合。
5. 每次只翻一个系统（不要 96 张一次全翻），回归通过再下一个。

## 四、注意事项（防踩坑）

- **升级不变占地**铁律：升级卡（Lv2/Lv3）不新增占地。
- **`status:"draft"` 不参与结算**：翻正前确认结算代码已读该卡，否则"翻正了但没效果"（BUG-G014 同类）。
- **参数纪律**：新卡的数值常数入 `balance.json`/`buildings.json`，禁内联。
- **模拟器先验**：每系统接入前，白机模拟器已有对应简化口径（学院链/居民区/消费池），黑机按同参数落 Unity。
- **编译锁**：Unity batchmode 不可并行（多 agent 会抢锁）。
