# 代码规范（黑机必须遵守）

> 状态：✅ R49 v1.0——院长 2026-10-29 定：**未来会有新地图/新阵营/新历史事件，开发不能写死太多东西**。
> 适用：黑机全部 C#/Unity 代码；白机文档中的示例也按此约束写。

## 一、数据驱动（硬性）

1. **城市/阵营/地图/事件/剧本全部数据化**：`cities.json`、`factions.json`、`maps/*.json`、`events/*.json`、`balance.json`；代码只读数据，不写死内容。
2. **禁止**在规则代码里出现 `if (cityId == "Beijing")`、`faction == "CN"`、`cityCount == 14`、`mapWidth == 2560` 这类硬编码；城市差异用 `tags[]`/`traits[]`/`modifiers[]` 数据表达。
3. **新增地图/阵营/事件 = 加数据，不改规则代码**；如需新规则，走"数据字段 + 通用解释器"，不写一次性分支。
4. 地图坐标/投影/城位/航线全部进 `maps/*.json`；运行时不得假设 14 城/东亚范围/固定红框。
5. UI 从数据生成：城市列表、阵营列表、事件选项、建筑列表都按数据表渲染；不写死数量/名称。

## 二、扩展点（至少保留这些接口）

```
MapDefinition   { id, size, projection, playArea, cities[], links[], terrainMask }
FactionDefinition { id, name, color, ideology, traits[], startCities[], startArmy }
CityDefinition  { id, mapId, name, owner, motherNation, population, capacity,
                  baseLivability, baseSecurity, culture, tags[], buildings[] }
EventDefinition { id, trigger{type,conditions}, once, priority, effects[], textRefs }
ScenarioDefinition { id, mapId, factions[], events[], victoryOverrides }
```

- 新剧本 = `ScenarioDefinition` 组合现有 Map/Faction/City/Event；不复制代码。
- 事件效果用枚举+参数（`ModifyLoyalty`, `SpawnFaction`, `TransferCity`, `AddPopulation`…），脚本不写 C#。
- 数值常量全部进 `balance.json`；代码里不出现魔法数。

## 三、存档与兼容

- 存档带 `version`；新增字段必须可缺省（旧档读入给默认值），未知字段读取时**保留**，不丢。
- 城市/阵营/事件用稳定字符串 ID，不用数组下标；新地图/新阵营加入不破坏旧档。
- 地图切换/新剧本开局走同一 `GameState` 初始化路径，不写第二套。

## 四、测试与验收

1. **新图烟雾测试**：加载一张 3 城测试图 + 2 阵营，跑 20 回合不崩、HUD/面板正常。
2. **新阵营烟雾测试**：加一个 `factions.json` 条目，开局/外交/战斗识别正常。
3. **新事件烟雾测试**：加一个 `EventDefinition`（无代码），触发/效果/战报正常。
4. **数值回归**：改 `balance.json` 后跑 `tools/verify_*.py`/沙盘脚本，关键量（人口/粮/忠诚/军力）不越界。
5. 代码评审清单：有没有硬编码城市/阵营/地图尺寸/数量？有没有绕过数据表的新分支？存档缺字段会不会崩？

## 五、王乐添类剧情事件

- 固定事件（第 2 回合王乐添自立）走 `EventDefinition`：`trigger={type:"turn", turn:2}`，`effects=[TransferCity(台北,WLT), SpawnFaction(WLT,...), ModifyRelation(CN,WLT,-20)]`；**不写死在 C#**。
- 第 1 回合锁定台北/王乐添用 `EventDefinition` 的 `lock` 效果或 `ScenarioDefinition` 的 `lockedCities/lockedGenerals`，同样数据化。
- 新剧本可替换为别的固定事件（同一解释器）。

## 六、黑机执行

- 每次开工先读本文件；新增内容先问"这是数据还是代码"；能数据化就不写分支。
- PR/提交说明里注明：新增了哪些数据字段/扩展点；有没有破坏旧档/旧图。
- 与 `docs/06-设计/00-总纲/数值公式总纲.md` 配套：公式参数进 `balance.json`，代码只实现公式解释器。
