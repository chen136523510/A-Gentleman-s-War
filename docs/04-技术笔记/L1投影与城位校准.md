# L1 投影与城位校准（R24g 定稿）

> 本文是"底图城盘 / 城名标签 / 航线 / 悬停"四者同源的唯一配方。
> 相关：`tools/bakery/paint-map.js`（JS 投影）、`Assets/_Project/Scripts/L1/L1World.cs`（C# 投影）、
> `tools/bakery/bake.html?mode=cities`（城盘烘焙）、`Assets/_Project/Data/cities.json`（dx/dy）。

## 一、坐标系

- 世界 = Seedream 底图 2560×1440，**1px = 1 世界单位**；Unity 世界原点在地图中心，y 向上。
- 烘焙画布坐标（canvas，y 向下）：`canvas_x = 1280 + sx`，`canvas_y = 720 − sy`。
- 经纬度 → 投影屏幕坐标（烘焙/校准统一用这个）：
  ```
  px = 1280 + (ne1(lon,lat).x − C0.x) * S * StretchX
  py =  720 − (ne1(lon,lat).y − C0.y) * S
  ```
  `S=1150`、`StretchX=1.182`、`C0=ne1(126°,17°)`；澳洲城先做 `AuK=0.62` 绕 `AuC(133,−7)` 缩放 + `auShift=30°` 北移。
- `cities.json` 的 `dx/dy` 是投影后的屏幕像素微调：
  ```
  anchor_px = (px + dx, py + dy)
  ```
  Unity 侧 `L1City.Anchor = Proj(lon,lat) + (dx, −dy)`（y 已翻成向上）。

## 二、⭐ 历史根因：Unity 漏乘 StretchX（R24g 修）

R24b 把底图横向拉伸 1.182，烘焙 JS 的 `proj()` 乘了 `STRETCH_X`，但 `L1World.Proj` 只乘了 `S`。
后果：烘进底图的城盘在拉伸后的位置，Unity 的标签/航线/悬停却按未拉伸的 x 摆放——
**越靠东错位越大**（悉尼约 63px），表现为"城名离城、悬停不对、航线不接城"。
R24e 只把城盘烘焙侧校准了，运行时未同步，所以"构造性同步"并未真正成立。
修法：`L1World.Proj` 的 x 乘 `StretchX`。**改投影参数时 JS/C# 两处必须同时改。**

## 三、城位校准操作配方

1. 打开干净底图 `tools/bakery/out/refined-content.png`（2560×1440，无城盘；若被 AI 城区污染先跑 `patch_au_city.py`）。
2. 在图上逐城读目标像素位（用 25px 网格放大裁切，读城盘底边中心；沿海城让城盘中心落在陆地/海岸）。
3. 按 §一公式算 `px/py`，写 `dx = 目标x − px`、`dy = 目标y − py`（保留 1 位小数）。
4. 起烘焙服务 `python tools/bakery/serve_upload.py`（8123 静态 / 8124 上传）。
5. 浏览器开 `http://127.0.0.1:8123/tools/bakery/bake.html?mode=cities` → 产出 `out/refined-cities.png`。
6. 覆盖 `Assets/_Project/Art/Map/L1-BaseMap-2x.png`（同名，meta/guid 不变）→ 重建 exe。
7. 验收：`AGW.exe -agwshot` 会自动出 `agw-shot.png`（开局）与 `agw-shot-au.png`（澳洲视角），
   2560×1440 原生、不需要窗口前台；再按 §五逐项看图。

## 五、红框可玩区（R24g）

院长验收图上的红框（截图 2559×1440）就是暂定可玩区：

```
PlayXMin=-122  PlayXMax=1227   (1158..2507 − 1280)
PlayYMin=-716  PlayYMax=480    (720−1436 .. 720−240)
PlayW=1349     PlayH=1196
```

- `L1CameraRig` 把视口四边钳在框内；`MinZoom = FitOrtho / min(PlayW/(2·aspect), PlayH/2)`，
  16:9 下 ≈1.897（视口 1349×759），框外卫星图不可见。
- 16:9 下最小缩放也看不全红框高度（1196 > 759），开局取 `InitY=-5` 看北京到北澳，向下拖拽看悉尼/墨尔本；
  想全框一屏只能加黑边/信箱，按院长"红框外暂不开放"的意图不采用。
- `SeaBackdrop` 已删：视口永远在底图内，不再需要图外海面兜底。

## 六、美术侧三个坑（R24g 已修）

1. **达尔文白色光球**：`darwin.png` 是"草地圆角方块+村落"，白底未抠净（71% 不透明），
   烘到 48px 就是白球。现策略：`bake.html` cities 模式跳过 `faction==="NONE"`，
   直接用 Seedream 底图自绘的达尔文村落；无主城也不加金晕。
2. **澳洲第三个"贴图"**：Seedream 底图自己画了一座城区（约 2310..2375, 1378..1435），
   和我们的悉尼/墨尔本叠成三个。跑 `tools/bakery/patch_au_city.py` 用左侧干净草地做
   均值/方差色彩迁移+羽化克隆抹除（供体 2000,1150；脚本内含坐标，换底图需重读）。
3. **城贴图白边**：Seedream 城市图自带近白边缘（190~225 灰白），只按纯白阈值抠会留一圈。
   `tools/bakery/rekey_cities_white_edge.py` 从图像边界泛洪（透明区视为可通行），
   只删连通白边、不伤城区内白色屋顶，再 2.5px 羽化。

## 七、标签 / 悬停

- 城名标签：`cities.json` 的 `lp`（t/tc/b/l/r/tl/tr/bl/br）决定相对城盘中心的方位；
  Text 必须显式 `MiddleCenter`，宽度用 `字数×字号` 估（`preferredWidth` 会虚高，新激活标签首帧可能为 0）。
- 城盘视觉中心 = 锚点 + 20 世界单位（烘焙时城图底边在锚点+4，高 48）。
  悬停判定用这个点，`HoverRadius=30`；tooltip 跟随鼠标 (18,−14)。
- 城名离城的排查顺序：①`L1World.Proj` 是否乘 `StretchX`；②cities.json dx/dy 是否按拉伸后的 px 算；
   ③底图是否用同一份 cities.json 重烘；④标签 `lp`/对齐/字宽。
