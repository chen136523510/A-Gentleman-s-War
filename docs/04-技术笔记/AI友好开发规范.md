# AI 友好开发规范（v1.0 · 2026-11-24 院长第 2/3 条）

> 目的：本产品体量大、AI 参与度高，**token 是真实成本**。本规范定义"AI 可读、易改、易检索、性能好"的硬标准，并给出项目现状巡检与改造优先级。
> 适用：`sim/`、`Assets/_Project/`、`docs/`、`tools/` 全部自有内容。
> 违反即视为技术债，新增内容必须达标；存量按 §五 优先级逐步改造。

## 一、本次会话实测的 token 浪费模式（数据说话）

| # | 模式 | 单次成本 | 占比 | 根因 | 规范对策 |
|:--:|---|:--:|:--:|---|---|
| 1 | **整块 Edit**（60 行卡表替换） | ~6k token | 20% | Edit 需回传 old+new 全文 | 数据独立成行级文件，改值只改 1 行（§二 P1） |
| 2 | **读大文件**（2436 行脚本读 700 行） | ~28k | 30% | 无 hook 标记，只能通读定位 | `@hook:` 标记，grep 定位（§二 P2） |
| 3 | **整篇 Write 报告**（400 行） | ~12k | 12% | 报告无骨架，每次全量重写 | 报告模板 + 分段 Edit，只改变动小节 |
| 4 | **重复轮次**（建议→裁→重写同段） | ~10k | 10% | 首盘把"建议"写成定稿式全文 | 首盘只出**数据 + 待裁问题清单**，不预写方案（§三 R1） |
| 5 | 长输出刷屏（场景跑 tail -30 ×12 次） | ~6k | 6% | 无可读的机器判定 | 断言 PASS/FAIL，人只看结论行（§二 P5） |
| 6 | 全量重跑验证 | ~8k | 8% | 每次全 200 回合 | 分层验证：audit(静态) → 20 回合 smoke → 200 全量 |

**结论：可消除 60%+**（#1 #2 #3 #4 均为结构性可修）。

## 二、五条核心原则

### P1 数据与逻辑分离（最高优先）

- **AI 频繁修改的数值 → 独立数据文件，一条记录一行**；代码只读数据。
- 行格式固定：`id` 在最左（grep 友好）；同字段顺序固定（diff 友好）。
- 目录：`sim/data/<主题>.js`（模拟盘共用）；Unity 侧已是 `Assets/_Project/Data/*.json`（同纪律）。
- **改数值 = 改 1 行**，永不触碰逻辑文件。

```js
// sim/data/cards.js —— 一行一张卡，id 在最左
{ id: 'privatization', attr: 'eco', mutex: 'industry', fx: { comm: 1.15, pool: 1.025 } },
```

### P2 定位先于阅读（`@hook` 标记）

- 每个可调落点在代码里必须有**唯一标记**：`// @hook:<key>`。
- AI 定位流程固定：`grep -n "@hook:<key>"` → 只读目标行 ±40 行。
- 例：`// @hook:W` `// @hook:pool` `// @hook:relation` `// @hook:buildCost`。
- 一个 key 多处落点时全部标记（`grep` 一次全出）。

### P3 摘要先于正文（文档 AI 摘要块）

- 每份设计文档顶部必须有 **≤12 行摘要块**：

```md
> **AI 摘要**：版本 v3.0 已定版 ｜ 数值源=`sim/data/cards.js` ｜ 待裁项：无
> 关键数值：见 §12.4 表 ｜ 关联：架构 v0.7 / 索引-决策 11-24
```

- AI 默认**只读摘要块**即可回答"现状是什么"；下钻才读正文小节。

### P3.1 拆分零失真铁律（院长 11-24 第 1 条）

- **文档拆分只做物理切分，不改写任何原有行**；新增仅限导航/面包屑。
- 必须用**逐行多重集校验**：`原文件行多重集 == (新文件行多重集 − 新增行)`，行数守恒 `新合计 − 新增 = 原合计`。
- 切分脚本先做**段边界自检**（每段首行必须匹配预期标题），防行号漂移写坏内容。
- 拆分后必检外部链接：`grep "文档名.md#"` 查锚点引用（本项目政策专题=0 处，安全）；旧章节号引用（如 `§5.12`）随拆分更新指针。

### P4 单次窗口预算（硬阈值）

| 对象 | 上限 | 超出动作 |
|---|---:|---|
| 数据文件（卡表/建筑/参数） | **400 行** | 按属性/模块拆文件 |
| 代码文件（sim 脚本/Unity 单类） | **600 行** | 拆模块 |
| 设计文档 | **600 行** | 拆子文档 + 索引 |
| 单条记录 | **1 行** | 长描述进子文档 |
| 单次工具读窗口 | **150 行** | 先 grep 定位 |
| 单次任务触及文件 | **3 个** | 拆分任务单 |

### P5 断言先于观测（模拟盘）

- 每个模拟场景必须输出**机器判定行**：`[ASSERT] 关系封顶=FAIL(100/100)` / `[ASSERT] 未接线=0 PASS`。
- AI 只看 ASSERT 汇总 + 结论行；完整表格落 `tmp/`。
- 分层验证顺序：`audit`（静态 0 回合）→ `smoke`（20 回合）→ `全量`（200 回合 × N seed）。

## 三、行为纪律（AI 执行侧）

| # | 纪律 | 说明 |
|:--:|---|---|
| R1 | **首盘只出数据，不预写方案** | 验证类任务：输出"指标 + 异常 + 待裁问题清单"；**不写"建议改成 X"的完整表格**——院长裁定后再动文档（本轮教训） |
| R2 | **改值前先 grep 数据文件** | 禁止凭记忆改（防多份副本不一致） |
| R3 | **一次会话只改一个主题** | 跨主题改动拆窗口（AGENTS §八 已有） |
| R4 | **禁止整篇重写文档** | 用分段 Edit，只碰变动小节 |
| R5 | **过程件进 `tmp/`，成品进 `sim/`** | 已有纪律，重申 |
| R6 | **同一结论只落一处权威源** | 数值进数据文件/卡表；决策进索引-决策；其他文档只链接（防多处不一致引发返工） |
