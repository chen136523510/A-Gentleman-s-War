# AI 友好开发规范（v1.0 · 2026-11-24 院长第 2/3 条）

> 目的：本产品体量大、AI 参与度高，**token 是真实成本**。本规范定义"AI 可读、易改、易检索、性能好"的硬标准，并给出项目现状巡检与改造优先级。
> 适用：`sim/`、`Assets/_Project/`、`docs/`、`tools/` 全部自有内容。
> 违反即视为技术债，新增内容必须达标；存量按 §五 优先级逐步改造。

## 一、本次会话实测的 token 浪费模式（数据说话）

| # | 模式 | 单次成本 | 占比 | 根因 | 规范对策 |
|:--:|---|:--:|:--:|---|---|
| 1 | **整块 Edit**（60 行卡表替换） | ~6k token | 20% | Edit 需回传 old+new 全文 | 数据独立成行级文件，改值只改 1 行（§二 P1） |
| 2 | **读大文件**（2436 行脚本读 700 行） | ~28k | 30% | 无 hook 标记，只能通读定位 | `@hook:` 标记，grep 定位（§二 P2） |
| 3 | **整篇 Write 报告**（400 行） | ~12k | 12% | 报告无骨架，每次全量重写 | 报告模板 + 分段 Edit，只改变动小节 |
| 4 | **重复轮次**（建议→裁→重写同段） | ~10k | 10% | 首盘把"建议"写成定稿式全文 | 首盘只出**数据 + 待裁问题清单**，不预写方案（§三 R1） |
| 5 | 长输出刷屏（场景跑 tail -30 ×12 次） | ~6k | 6% | 无可读的机器判定 | 断言 PASS/FAIL，人只看结论行（§二 P5） |
| 6 | 全量重跑验证 | ~8k | 8% | 每次全 200 回合 | 分层验证：audit(静态) → 20 回合 smoke → 200 全量 |

**结论：可消除 60%+**（#1 #2 #3 #4 均为结构性可修）。

## 二、五条核心原则

### P1 数据与逻辑分离（最高优先）

- **AI 频繁修改的数值 → 独立数据文件，一条记录一行**；代码只读数据。
- 行格式固定：`id` 在最左（grep 友好）；同字段顺序固定（diff 友好）。
- 目录：`sim/data/<主题>.js`（模拟盘共用）；Unity 侧已是 `Assets/_Project/Data/*.json`（同纪律）。
- **改数值 = 改 1 行**，永不触碰逻辑文件。

```js
// sim/data/cards.js —— 一行一张卡，id 在最左
{ id: 'privatization', attr: 'eco', mutex: 'industry', fx: { comm: 1.15, pool: 1.025 } },
```

### P2 定位先于阅读（`@hook` 标记）

- 每个可调落点在代码里必须有**唯一标记**：`// @hook:<key>`。
- AI 定位流程固定：`grep -n "@hook:<key>"` → 只读目标行 ±40 行。
- 例：`// @hook:W` `// @hook:pool` `// @hook:relation` `// @hook:buildCost`。
- 一个 key 多处落点时全部标记（`grep` 一次全出）。

### P3 结构先于文本（结构化数据，非摘要块）

**院长 2026-11-24 第 1 条纠正**：要的是**结构化数据**（批量阅读/批量操作），**不是自然语言摘要块**——摘要块本身会漂移，且 AI 读它仍要解析语义。

| 数据类型 | 结构化载体 | 说明 |
|---|---|---|
| **文档台账**（243 篇的版本/状态/同步日期/依赖/stale） | [`docs/meta/docs-index.json`](../../docs/meta/docs-index.json) | 紧凑数组格式 **34 KB ≈ 10k token**，一次读完掌握全部文档状态（替代逐篇读头部）；由 `sim/tools/doc-sync.js gen` 生成，**勿手改** |
| **政策卡数值**（52 张） | [`sim/data/cards.js`](../../sim/data/cards.js) | 一条一卡，改值只改 1 行 |
| **参数常数** | [`索引-参数.md`](../../docs/06-设计/00-总纲/索引-参数.md) 表格 | 参数ID→值→出处，机器可 grep |
| **决策** | [`索引-决策.md`](../../docs/06-设计/00-总纲/索引-决策.md) 表格 | 日期→专题→裁定→理由 |

**批量操作**：`node sim/tools/doc-sync.js who <文件>`（改前查影响面）· `stale`（查同步债）· `scan`（全景统计）· `gen`（刷新台账）。

### P3.0 同步义务的机器判定（替换"靠人自觉"）

- 文档头部声明 `syncDate`（我已同步到此日）= 同步承诺；**只有声明者有同步义务**。
- `stale ⟺ 头部引用的上游 git 最后提交日 > 本文档 syncDate`。用 git 时间，不用"文档 commit 时间"（改错别字也会刷新 commit，会误报）。
- 零人工维护：改完任何设计文档 → `doc-sync stale` → 列出所有需回写的词条 → 改完 syncDate 归零。
- 未声明 syncDate 的文档不判 stale，但**百科词条与 00-总纲 核心文档必须声明**。

### P3.1 拆分零失真铁律（院长 11-24 第 1 条配套）

- **文档拆分只做物理切分，不改写任何原有行**；新增仅限导航/面包屑。
- 必须用**逐行多重集校验**：`原文件行多重集 == (新文件行多重集 − 新增行)`，行数守恒 `新合计 − 新增 = 原合计`。
- 切分脚本先做**段边界自检**（每段首行必须匹配预期标题），防行号漂移写坏内容。
- 拆分后必检外部链接：`grep "文档名.md#"` 查锚点引用（本项目政策专题=0 处，安全）；旧章节号引用（如 `§5.12`）随拆分更新指针。

### P4 单次窗口预算（硬阈值）

| 对象 | 上限 | 超出动作 |
|---|---:|---|
| 数据文件（卡表/建筑/参数） | **400 行** | 按属性/模块拆文件 |
| 代码文件（sim 脚本/Unity 单类） | **600 行** | 拆模块 |
| 设计文档 | **600 行** | 拆子文档 + 索引 |
| 单条记录 | **1 行** | 长描述进子文档 |
| 单次工具读窗口 | **150 行** | 先 grep 定位 |
| 单次任务触及文件 | **3 个** | 拆分任务单 |

### P5 断言先于观测（模拟盘）

- 每个模拟场景必须输出**机器判定行**：`[ASSERT] 关系封顶=FAIL(100/100)` / `[ASSERT] 未接线=0 PASS`。
- AI 只看 ASSERT 汇总 + 结论行；完整表格落 `tmp/`。
- 分层验证顺序：`audit`（静态 0 回合）→ `smoke`（20 回合）→ `全量`（200 回合 × N seed）。
- **断言要测真目标，不是测易测项**（2026-11-24 教训）：
  - ❌ 反例：用"删除行数 ≤8"判"信息不失真"——删除行数只是代理指标，与真目标脱钩；合法删除被误判，语义歪曲检测不出，还会诱导"只加指针不动正文"的敷衍回写。
  - ✅ 正例：**事实点对账**（关键数值/规则是否与上游一致、已作废的是否标注）+ 指针有效性（路径存在且目标有对应章节）。
  - **判据自身要测试**：本轮验收 regex 连续 3 次假阴性（"关系/声誉流"匹配不到"关系流"、`反谍+1` 的 `+` 被当量词）——判据写完必须先对自己已知为真的样本跑一遍。

## 三、子 Agent 使用范式（2026-11-24 实测评估 · 院长要求验证）

> 实验：把"批量回写 stale 文档"交给 3 个子 agent 并行（各 4~5 篇），主会话只写任务单 + 验收。

### 3.1 实测结果

| 维度 | Agent A（00-总纲 5 篇） | Agent B（03-内政 5 篇） | Agent C（04-军事 4 篇） | 合计/评价 |
|---|---:|---:|---:|---|
| **tokens** | **7.16 M** | **5.69 M** | **4.02 M** | **16.9 M** |
| 工具调用 | 98 | 74 | 68 | 240 |
| 耗时 | 370s | 253s | 280s | 并行 ~6 分钟 |
| 质量 | 5/5 通过 | 5/5 通过 | 4/4 通过 | **14/14 指针有效、14/14 脱离 stale、断链 0** |
| 独立发现 | 政策卡架构实为 v0.7（非任务单所说 v0.8，未擅改）；maxWars 事实与原文不符（sim=2 非 1）；数值公式总纲内部矛盾 | 政策卡内容专题自身矛盾（§十一 残留 resistPub）；"能源并入生产力"非纯取代 | 连通图"西安→深圳"本不邻接；间谍负伤 5 vs 8 回合内部冲突；**明确拒绝猜"突袭士气"** | 均超预期 |

### 3.2 结论：**质量可行，成本不可行（当前形态）**

| 判定 | 说明 |
|---|---|
| ✅ **任务单=知识注入 可行** | 任务单给"已知上游变更 + 三件事 + 禁止清单 + 验证命令"，子 agent 能独立产出合格结果，且能发现任务单没覆盖的问题 |
| ✅ **客观验收 可行** | 14/14 通过机器判定（指针有效性/事实点/stale 消失/断链），不依赖自述 |
| ❌ **成本 280 倍** | 16.9M tokens / 14 篇 ≈ **1.2M token/篇**；主会话手工做（批次 1）≈ 4k token/篇 → **~300:1** |
| 🔑 **根因** | 子 agent **无主会话上下文**：权威源关系、上游变更、文档结构都要重新探索；每次工具调用（68~98 次）都带完整上下文重算 |

### 3.3 正确分工（范式 v2）

| 任务类型 | 用什么 | 理由 |
|---|---|---|
| **结构固定的批量操作**（加指针/改 syncDate/标注作废） | **脚本 + 数据表** | 批次 1 已验证可模板化；成本 <1k token/篇 |
| **需要判断的语义工作**（"抵抗删除影响哪些段落"） | **主会话** | 上下文已在手里，子 agent 重探索=300 倍成本 |
| **完全独立、主会话无上下文的探索**（全库搜引用、跨模块影响面） | **子 agent** | 这才是价值区：并行、不污染主上下文 |
| 多轮试错的长任务 | 子 agent（需精确任务单） | 可并行但要控制迭代次数 |

### 3.4 子 agent 任务单模板（要点）

1. **自包含**：子 agent 读不到主会话历史——项目背景、文件路径、验证命令全写清。
2. **给精确信息**：不要只给"已知上游"，要给"具体改哪行/改成什么/哪些是挂起项"（A/C 都指出我给的"已知上游"与实际 stale 源不符，导致额外探索）。
3. **禁止清单要具体**：如"表格行标注加在最后一个单元格内"（B 指出"行末加标注"对 markdown 表格有歧义）。
4. **要求自报不确定**：明确"不确定就如实说不要猜"——C 因此拒绝猜突袭士气，A 拒绝擅改版本号。
5. **要求不提交 git**：多 agent 并行时由主会话统一提交（三组都自觉遵守）。
6. **限制预算**：明确"最多读 N 个文件/不通读上游，用 grep 定位"（本轮无预算约束是成本爆炸主因）。

> **一句话**：子 agent 适合"探索 + 并行"，不适合"我已掌握上下文的批量执行"；**任务单给得越精确，成本越低**。

## 三、行为纪律（AI 执行侧）

| # | 纪律 | 说明 |
|:--:|---|---|
| R1 | **首盘只出数据，不预写方案** | 验证类任务：输出"指标 + 异常 + 待裁问题清单"；**不写"建议改成 X"的完整表格**——院长裁定后再动文档（本轮教训） |
| R2 | **改值前先 grep 数据文件** | 禁止凭记忆改（防多份副本不一致） |
| R3 | **一次会话只改一个主题** | 跨主题改动拆窗口（AGENTS §八 已有） |
| R4 | **禁止整篇重写文档** | 用分段 Edit，只碰变动小节 |
| R5 | **过程件进 `tmp/`，成品进 `sim/`** | 已有纪律，重申 |
| R6 | **同一结论只落一处权威源** | 数值进数据文件/卡表；决策进索引-决策；其他文档只链接（防多处不一致引发返工） |
