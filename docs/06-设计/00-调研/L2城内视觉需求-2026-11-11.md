# L2 城内视觉与 UI 需求（院长 2026-11-11 批注）

> 来源：院长对 L1/L2 实机截图的两张批注（2026-11-11）。本文只记录**视觉相关**需求，暂不实施；非视觉项（去迷雾/删探索/点城名进城/面板迁移等）已在代码中落地，见根目录 CHANGELOG。
> 截图原图属会话过程件，不入库。

## 一、视角与场景

| # | 需求 | 说明 / 待定 |
|---|---|---|
| V1 | **不要 90° 俯视，要有一点倾斜** | 当前 L2 为正俯视（正交、纯顶视）。目标观感参照三国志 12：斜俯视、能看到建筑立面与地形起伏 |

| V3 | **优化美术与结果表现** | 地形/建筑/植被观感、建造完成表现、结算结果的视觉呈现 |

## 三、L1 UI（已落地部分）

- 国级面板移除「民生」（民生归城级，进 L2 第二行）。
- 「国防」改「城防」。
- 城市功能面板（军事/建造/城内等）迁入 L2；L1 点击敌城仅弹情报卡。
- 点击己方城名直接进 L2。
- L1 不做迷雾：全图与 14 城常显；探索/详情入口删除。

## 四、视角路线对比（待裁）

| 方案 | 做法 | 成本 | 风险 |
|---|---|---|---|
| **A. 2.5D 斜视烘焙（推荐先做）** | 地形按斜俯视重烘（3072²/4032²），建筑 sprite 带立面与投影；相机保持正交斜视 | 复用现有 `bake_terrain.py` / `bake_buildings.py`，改投影与绘制参数 | 无法自由旋转；遮挡需按图层处理 |
| **B. 3D 建模** | URP 3D 场景 + 建筑/地形模型，可旋转/缩放/真实光影 | 推翻现有 2D 烘焙管线与全部建筑图，美术量最大 | 与"单机 exe 发给朋友"的时间预算冲突 |

**建议**：先用 A 做深圳金样本，验证斜视观感；若院长仍要 3D，再在批量烘焙 14 城前切换，避免全量返工。

## 五、待院长后续拍板

1. 视角选 A（2.5D 斜视）还是 B（3D）？
2. 倾斜角度/投影方向（如俯角 55°~65°、固定朝北）。
3. 建筑是否保留 sprite 立面 + 投影，还是做简模。
4. UI 皮（双皮 vs 统一漆木皮）——影响 V7/V8。

## 六、下窗口调研议程（2026-11-13，院长定：美术优先）

> 目标：**批量烘焙 14 城前**定 L2 视角路线，先出深圳金样本；不拍板不批量。

1. **先读**：本文 §四 + [ADR-012](../../02-决策/ADR-012-L2渲染底座v4空地制与红警式建造.md) + [L2地图规划与烘焙管线](../04-技术笔记/L2地图规划与烘焙管线.md) + [L2地图档案](../L2地图档案/) + [UI 雏形规划](../07-技术架构/UI雏形规划.md)。
2. **A/B 对比**：
   - **A 2.5D 斜视烘焙（推荐先做）**：复用 `bake_terrain.py` / `bake_buildings.py`，改投影与绘制参数；正交斜视 **55°~65°**、固定朝北；建筑 sprite 带立面 + 投影；遮挡按图层/前后关系处理。
   - **B 3D 建模**：URP 3D + 建筑/地形简模，可旋转/缩放/真实光影；美术量与时间预算最大，与“单机 exe 发给朋友”冲突。
3. **深圳金样本**：同一套底图/建筑，A 方案出 2~3 个俯角/朝向对比图；检查立面、投影、遮挡、道路/地块透视一致性；院长拍板后再批量 14 城。
4. **资产管线**：底图 3072²/4032² 预算；建筑 stage0~3 / idle / overlay / sheet；阴影/接地；L2 地块 shader；ComfyUI 本地出图免费，**付费 API 先确认**。
5. **UI 联动**：V7 建造目录正式美术（分组/解锁态/造价）；V8 统一视觉语言；UI 皮（双皮 vs 统一漆木皮）与视角一起定。
6. **产出**：路线决定 + 深圳金样本截图 + 批量烘焙参数 + 资产登记；落 `docs/02-决策/` 或 L2 档案，更新 handoff。

**下窗口待裁**：A/B；俯角与固定朝向；建筑 sprite 立面 vs 简模；UI 皮；批量烘焙是否等金样本验收。
