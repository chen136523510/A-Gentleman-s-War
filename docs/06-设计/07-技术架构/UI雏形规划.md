# UI 雏形规划（界面先行）

> 状态：🗄️ Web 雏形已归档（R15~R17，产物在主仓 `poc/guonanzhi-ui/`）；**九屏清单=Unity UI 需求底稿**；L1 战略层首版已实装（R37c）· 更新：2026-10-26 R37c
> 原则：**界面先行、逻辑假数据**——雏形只定布局/交互/信息密度，不接任何游戏逻辑（不接指令总线/存档）。目的：把前 14 轮设计文档落到可见界面上，暴露机制矛盾，并倒逼悬而未决项（L2 网格基点等）拍板。
> L1 Unity 大地图 HUD 具体布局（右上主面板/顶部条/左下城市面板/右下禁放 + 城名字标）见 [L1大地图HUD布局.md](./L1大地图HUD布局.md)（R24h v0 提案，待院长走查）。

## 为什么 UI 雏形先行（R15 白机理由，院长认可方向）

1. 设计文档已经够厚，纯文字讨论边际递减；界面落地是最快的矛盾检测器；
2. R14 内容目录 v1（产业 14+娱乐 10+居民楼四型）刚好当假数据，界面有货可摆不空转；
3. 院长意愿=先把界面设计好；UI 定型后数据结构呈现方式确定，后续模块（兵种/科技树）有了挂载点。

## 假数据原则

- 全部占位数值，写死在组件里，不接指令总线/存档/真实结算；
- 可点击跳转模拟真实动线（L1 点城进 L2、点地块弹建造面板）；
- 雏形定型后按 07 架构拆正式组件，不推倒重来。

## 双机分工（R24i 定稿）

- **黑机**：全部代码/美术/构建/场景（Unity UI 实装、出图、打包验收）；
- **白机**：仅文档（界面规划/规格/文案），完全不接触代码；
- 详见 `AGENTS.md` §三。

## 技术基线（R18 ADR-009 起）

- **Unity 2022.3.62f3c1 LTS 中国版 + URP 2D**；UI 用 uGUI（运行时程序化构建，见 `L1MapBuilder`），数据走 `Assets/_Project/Data/*.json`；
- L1 大地图=离线烘焙大纹理 + 运行时 Sprite/航路/标签叠放；
- Web 雏形（`poc/guonanzhi-ui/`，Vue UMD）已归档主仓，只作交互与信息密度参考，**不再作为正式技术基线**。
