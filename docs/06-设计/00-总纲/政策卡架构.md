## 二、概念定义

### 2.1 五属性与五槽

`军事 military / 经济 economy / 文化 culture / 外交 diplomacy / 通用 universal`

| 属性 | 卡色 | 槽位（基础） | 只装 |
|---|---|:--:|---|
| 军事 | **红** | 2 | 军事属性卡 |
| 经济 | **黄** | 2 | 经济属性卡 |
| 文化 | **紫** | 2 | 文化属性卡 |
| 外交 | **绿** | 2 | 外交属性卡 |
| 通用 | **白** | 2 | 通用槽：任意属性卡；属性通用卡只进通用槽 |
| **合计** | — | **10** | — |

- 基础槽 **2/2/2/2/2 = 10**（院长"22222"口径）；**无政体加成**，所有阵营相同。
- 槽位可通过**事件、典藏等**额外获取（§5.2）；**不设硬上限**（获取频率/数量由难度参数控制）。
- 属性通用卡（白卡）只能进通用槽；属性专属卡可进同属性槽或通用槽。

### 2.2 统一卡池

- **初始卡池全阵营统一**：所有阵营开局看到同一套卡（已解锁部分），**无政体/阵营专属池**。
- 阵营差异由**大统领特性 + 武将**决定，不由政策卡池决定。
- 解锁差异来自**科技路线/事件**（不同阵营走到不同节点、遇到不同事件），不是初始池差异。
- 内容量完成态：**引擎已落库 51 张（初始 50 + environmentalism event）**；设计池 **52 张（+carbonQuota 提案）**待 `policies.json` 落库；**“初始”是卡属性（`initial`），不是独立池**。

## 三、系统分层

| 层 | 内容 | 归属 |
|---|---|---|
| **L0 定义层** | 卡定义 / 剧本槽位覆写 | 数据（JSON） |
| **L1 派生层** | 可装池（已解锁+槽型+槽位）/ 槽布局 | 规则（只读） |
| **L2 状态层** | 已装卡 / 槽位冷却 / 解锁集合 / 额外槽 | GameState |
| **L3 规则层** | 装配校验 / 编辑态方案 / 批量确认 / 发卡 / 加槽 | 政策系统核心 |
| **L4 效果层** | 修正器聚合 / 结算顺序 / 预览快照 | 各系统公式 |
| **L5 表现层** | 政策面板（查看/编辑）/ 卡色 / 确认 / 重置 / 冷却 | UI |
| **L6 AI 接口层** | 候选集 / 方案预览 / 批量提交 | **AI 专题** |
| **L7 持久层** | 存档 schema / 迁移 | 存档 |
| **L8 模拟层** | 规则参数化 / 事务闭环 / 效果占位 | sim |

## 四、数据模型

```
PolicyCardDefinition {
  id, name,
  attribute: military|economy|culture|diplomacy|universal,
  exclusiveGroup?: string,                  // v0.5：互斥组（同组最多装 1 张）
  initial: true|false,                      // 是否进初始卡池（属性，不是独立池；特殊卡=false）
  acquire: initial|proposal,                // 获取方式：initial=开局可得；proposal=外交提案发卡（§七.2）
  effects: [{ param, op: mult|switch|bias, value }],
  costs:   [{ param, value }],              // 可选；绝大多数卡为空
  unlock:  { type: tech|event|start },      // 解锁条件（只留科技/事件/开局）
  phase:   early|mid|late,
  color:   red|yellow|purple|green|white,   // 由 attribute 派生
  tags:    []
}

ScenarioDefinition.policySlots {
  base: { military:2, economy:2, culture:2, diplomacy:2, universal:2 },
  extraSlots?: [...]                        // 剧本预置额外槽（可选）
}

GameState.policies[factionId] {
  slots: {
    military:  [cardId...], economy: [cardId...], culture: [cardId...],
    diplomacy: [cardId...], universal: [cardId...]
  },
  slotUnlockTurn: { military:int, economy:int, culture:int, diplomacy:int, universal:int },
  unlocked: [cardId...],
  extraSlots: { military:int, economy:int, culture:int, diplomacy:int, universal:int }
}
```

- 无 `governmentId`、无政体字段、无时代字段。
- 卡 id 稳定字符串；未知卡 id/未知字段保留。

## 五、槽位与冷却

### 5.1 基础槽

- 2/2/2/2/2 = 10；所有阵营一致。
- 剧本可覆写 `policySlots.base`（副本/教学特例）。
- **无政体加成、无科技加槽**；加槽只走事件/典藏（§5.2）。

### 5.2 额外槽获取（院长 11-17）

| 来源 | 机制 | 接口 |
|---|---|---|
| **事件** | 事件效果给指定属性 +1 槽 | `grantPolicySlot(faction, attribute, 1)` |
| **典藏** | 典藏套装/文物效果给 +1 槽 | 同上 |
| **外交提案** | 特殊提案可发卡（不是加槽） | `grantPolicyCard(...)`（§七） |

- 额外槽**永久**（本局）；**不设硬上限**，获取频率/数量由**难度参数**控制。
- UI 在槽位区显示"基础 2 + 额外 N"。

### 5.3 槽位冷却（11-19 定稿：收费窗口 · 收费只由冷却决定）

- **装卡免费**（含首次装卡；原"装卡 100 财"作废——院长 11-19 第二轮裁，免玩家初次大额支出）。
- **冷却期（至 `slotUnlockTurn` = 装卡回合 + 2）内改动该槽：100 财/次**（卸/换均计）。
- **冷却期满后改动该槽：0 财**（鼓励长期调整）。
- 卸卡：冷却期内 100、冷却期外 0、不触发新冷却；卸后再装受原冷却约束。
- 批量确认时，只有**实际发生装/换**的槽位进入冷却。

## 六、装配与事务

### 6.1 动作与成本

| 动作 | 成本 | 冷却 | 次数 | 生效 |
|---|---|---|---|---|
| 装卡 | **0**（免费；11-19） | 该槽进入冷却（`slotUnlockDelay=2`） | 无每回合上限 | 确认后下一次结算 |
| 换卡 | 冷却期内 **100**（卸旧卡）/ 冷却期外 **0** | 新卡槽进入冷却 | 同上 | 确认后 |
| 卸卡 | 冷却期内 **100** / 冷却期外 **0** | 不触发 | **无次数** | 确认后 |

### 6.2 编辑态与预览确认（保留）

1. 进入编辑态，记录 baseline（当前已装+基础数值快照）。
2. 自由搭配（校验解锁/槽型/槽位可用（冷却内可付费改）/槽有空位；财在确认时校验）。
3. **数值预览**：显示直接基础数值变化（如"回合财 +25""征募费 −20%"）；乘区/条件效果只标"影响 XX"，不显示数值。
4. **确认按钮显示总消耗**（取始末差异：冷却期内改动次数 ×100；装卡与冷却期外改动免费；反复调整只算最终差异）。
5. **重置**恢复 baseline；取消不扣费不生效。
6. **预设配置（v0.5）**：面板内置三套预设（军事/经济/文化各一套 10 槽方案），一键套用后进入编辑态预览，玩家可微调或直接确认；用于降低决策负担，配合"低频政策"定位。

### 6.3 批量确认校验

1. 每张卡已解锁（科技/事件/开局）；
2. 槽型合法（五属性对五槽；属性通用卡只进通用槽）；
3. 目标槽有空位（基础+额外槽）；冷却期内改动该槽需 100 财（计入总消耗）；
4. **互斥组无冲突**（v0.5：同 `exclusiveGroup` 最多装 1 张，无论槽位）；
5. 财 ≥ 总消耗。

→ 扣费 → 写槽 → 装/换槽位进入冷却 → 刷新修正器 → 日志。
→ 失败不扣费不应用，就地提示（互斥冲突显示"与已装卡冲突：XX"）。

### 6.4 无政体变更

- **没有政体切换、没有清空卡槽、没有 1k 财、没有政体冷却**。
- 阵营倾向由大统领特性影响（游戏里自然产生，不专门写规则），不做政体/剧本事件。

## 七、解锁、发卡与加槽

### 7.1 解锁（只留两类）

- `tech`：科技树节点解锁卡（各线节点可挂卡）。
- `event`：事件奖励/剧情发卡。
- 初始卡池统一；无政体/阵营解锁。

### 7.2 外交提案发卡（新机制，细则=外交内容专题 v0.4 已定稿）

- 提案通过后，给**每个阵营**发一张卡（如环保提案→通用"环保主义"卡）。
- 发卡带 `mandatory` 标记：**要求挂着；不挂=违约**（违约后果已定=外交内容专题 v0.4：违约=撕毁/rep−3/关系−15/−8/CB 按提案）。
- 接口：`grantPolicyCard(faction, cardId, { mandatory:true, source:proposalId })`。
- UI：收到强制卡时提示"提案义务：需挂载，否则违约"。
- **细则（义务期/违约=撕毁/按提案 CB）已在外交内容专题 v0.4 定稿（11-19）。**

### 7.3 槽位扩展

- 事件/典藏效果调用 `grantPolicySlot(faction, attribute, count)`；永久生效。

## 八、效果层

### 8.1 三型修正器

| 型 | 聚合 | 示例 |
|---|---|---|
| `mult` | 同参数相乘，受总上限约束 | 税率/产出/消费池/维护/征募费 |
| `switch` | 布尔与/或 | 移民管制/电子长城/碳排放配额 |
| `bias` | 同参数相加 | 外交关系流/侵略阈值/忠诚流 |

- 每卡必须引用主公式参数名；禁止虚空产出。
- 结算顺序：基础值 → 政策修正器 → 其他系统修正 → 封顶/取整。

### 8.2 强度纪律（院长 11-17）

- **绝大多数卡无负面**；卡占槽位=最大副作用。
- 少数高风险卡可带负面（须可感知）。
- 单卡参考带 ±15%（非硬上限）；乘区总上限登记。
- **52 张卡**作为内容量（初始 50 + 特殊 2 提案获取），规则保持简单。

### 8.3 低频设计（v0.5 · 院长令"政策卡不是玩法重点"）

- **卡=长期国策**：**初始 50 张 + 特殊 2 张（提案获取）**效果全常驻，无"战时/和平"条件型（v1.0 已改国防教育〔原尚武精神〕/战时经济）；玩家装一次可长期不管。
- **不设套利**：无"装卡即收益→卸卡"循环；效果下次结算起生效，卸卡即停。
- **冷却收费（11-19 定稿）**：装卡免费（免初次大额支出）；**冷却期内改动 100 财/次、冷却期外改动免费**——短期折腾有成本、长期调整无成本；同一槽最快 3 回合自然冷却（付费可提前）。
- **UI 降负担**：三套预设配置一键套用；面板不主动弹出、不做日常提醒。
- **不做高频玩法**：无政策任务/每周推荐/combo 挑战；AI 政策行为归 AI 专题。

## 九、可见性

| 视图 | 内容 |
|---|---|
| **默认** | 当前已有（已解锁）的卡；按五属性分组；已有但不可用（槽型不符/槽满）灰显 |
| **全展示** | 全部卡；分"当前可装/已有不可用/未获得"；未获得显示获取途径（科技/事件） |

- 四态：已装/可装/已有不可用（灰）/未获得（显示途径）。
- 不做隐藏卡/抽卡。

### 9.1 敌方/他国政策可见性（院长 2026-11-24 第 7 条：默认可见）

- **默认公开**：所有阵营**当前已装的政策卡**对外可见（外交面板/势力详情可查看他国卡组），与真实世界"外交政策是公开宣示"一致。
- **公开范围**：卡 id + 卡名 + 已装槽位；不含内部数值系数（数值由卡面统一展示，不区分敌我）。
- **不做**：隐藏/情报付费解锁；不做"假装装卡"欺骗机制（一期）。
- **AI 消费**：AI 决策层读取他国已装外交政策（`PolicyModifiers` 公开部分）做反制评估——v26 政策盘已实现（`cardGain` 对手姿态感知：对手强硬→我方温和/中立加分；对手弃武→我方强硬加分）。见[全量模拟-v26-政策盘](./全量模拟-v26-政策盘.md) §五。

## 十、与其它系统边界

| 系统 | 政策卡做什么 | 不做什么 |
|---|---|---|
| 大统领/武将 | 阵营特性由大统领特性表达 | 政策卡不承担阵营差异 |
| 科技 | 科技节点解锁卡 | 不替代科技树 |
| 事件 | 事件解锁/发卡/加槽 | 不做一次性事件效果 |
| 外交 | 提案发卡/违约 | 不替代外交行动/会议 |
| 典藏 | 典藏效果加槽 | 不替代典藏系统 |
| 建筑 | 改产出乘区/维护/工期 | 不直接产出 |
| 军事 | 改征募/兵工厂/忠诚/军管 | 不直接给兵/不替代 L3 |
| 环境 | 改排放/配额/碳账 | 不替代环境账本 |
| AI | 候选集/方案预览/批量提交 | 算法归 AI 专题 |

## 十一、AI 接口（归 AI 专题）

| 接口 | 内容 |
|---|---|
| `getPolicyCandidates(faction)` | 可装池（已解锁+槽型合法+槽可用（冷却内付费）+槽有空位） |

| `commitPolicyPlan(faction, plan)` | 批量确认（扣费/应用/冻结） |
| `grantPolicyCard/grantPolicySlot` | 发卡/加槽（事件/外交/典藏调用） |

## 十二、UI 信息架构

- **单一政策面板**（无政体区）：
  - 顶部：槽位统计（基础 2+额外 X）/ 财 / 强制卡义务提示 / **三套预设一键套用按钮**。

  - 底部：卡列表（默认已有/可切全展示，按属性分组）、编辑态数值预览、**确认（显示总消耗）**、重置、取消。
- 卡面颜色：军红/经黄/文紫/外绿/通白；卡列表按色分组。
- 教程锚点：首次打开面板/首次装卡/首次收到强制卡。
