## 一、问题定义（院长三问）

1. L2 是否必须"足够大、承载一场 L3 战役"？（现 96×96 格=1.92km，明显不够）
2. L2↔L3 强关联（同格网）是否值得做？
3. 各自为战+预设 L3 战场是否更优？（可减轻 L2 规划负担、军事建筑/城墙可删减）

## 二、行业四种模式（实证）

### 模式 A：同图开战（战斗=大地图上演算）

| 游戏 | 做法 | 与 AGW 的关系 |
|---|---|---|
| 三国志14 | 部队在大地图上移动/接战，战斗=自动演算+手动"单挑/战法"点缀 | 战斗无独立空间，兵力角标化 |
| 文明6 / 群星 / P 社四萌 | 单位在大地图格子接战，战斗=数值演算（战力/伤害公式） | 同上 |

**结论**：同图模式=战斗被抽象成演算。**与 AGW 的 L3 定位（RTK12 式实时会战）天然冲突**——AGW 的 L3 是"暂停/倍速的实时 RTT"（L3 战斗层开题 D 裁），不是演算。选 A 等于砍掉 L3 实时层（重大玩法降级）。

### 模式 B：独立战场图（会战制）——RTK12 本尊

| 游戏 | 做法 |
|---|---|
| 三国志12 | 城内图只做内政（设施/规模小）；**战斗切入独立会战图**（每城预制城战场景+野战场景，城门/本阵/据点布好） |
| 三国群英传系列 | 大地图+极简城内；千人战=独立战场 |
| 全面战争系列 | 战役地图（省域）+ 独立战场图（攻城战=按城预制；野战=按地形类型参数化生成） |

**结论**：B=各自为战的成功范本。关键实证：**战场不是每城"单独开发"——是"模板池"**（全战=地形类型×布局参数；RTK12=每城一张但结构复用度高）。攻城战的"这座城"感觉靠模板+参数（城门数/城墙造型/河流走向）呈现，不要求与城内图几何 1:1。

### 模式 C：同场景换镜头（L2/L3 同格网——本次被质疑的强关联设想）

**做法**：L2 城市格网直接承载 L3 战斗（拉高镜头=战场），军事建筑/城墙占 L2 格位、战斗在格位上发生。

| 利 | 弊 |
|---|---|
| 一份数据一层开发（理论） | **L2 必须战斗级巨大+精细**（美术量爆炸；承载战役≈全战战场尺度） |
| L2 规划=战场规划（布局有意义） | **玩家规划负担极重**（每格都要想战斗价值） |
| 城墙/军事建筑真实起作用 | 军事建筑膨胀（城墙/箭塔/营寨全要 L2 摆位） |
| | **与 L3 开题 E 裁冲突**（E1~E10 已裁独立 C# sim+30Hz+命令流——L3 本来就是独立层） |
| | 经营视角（俯瞰全城）与战斗视角（RTT 局部）互相牵制 |
| | **L2 不堪=问题放大**（院长核心顾虑） |

### 模式 D：场景进入式（骑砍）

大地图行军→进入实时战斗场景（城镇模板+地形生成）。沉浸最强，**开发量=全项目之最**（场景资产+地形生成系统），与单机经营+会战定位不符。排除。

## 三、关键洞察：表现各自为战 + 数据单向流动

四种模式的真正分歧在**表现层**；而"不用每城单独开发 L3"的诉求本质在**数据层**。拆开：

```
L1 大地图（战略）
   │ 城市数据（人口/驻军/城防/建筑等级/城墙等级/武将）
   ▼ 单向注入
L2 城内图（经营）——只管生产/建设/内政，尺度=经营舒适即可
   │ 开战时注入参数（守军=驻军+民兵池、城防=城墙等级×系数、
   │                  援军=周边城驻军、战场模板=该城 terrain/城门数）
   ▼ 参数实例化
L3 战场（RTT）——参数化战场模板池（按地形类型×城门/城墙/河流布局）
   │ 战果回写（占领/损毁/俘获）
   ▼
L1 战略结算
```

- **数据仍同源**（同一份 GameState/城市档案）——不违背"三层同一份数据"铁律的**数据面**；修订的是**表现面**：L3 战场几何不再要求=L2 格网几何
- **战场模板池**：预做 6~10 张精修战场（平原城/山地城/滨海口城/河流城/……），每城按档案参数实例化（城墙等级→墙体耐久与造型档、城门数→突破口、河流→咽喉点）——这就是"不用每城单独开发 L3"的落地答案（全战实证可行）
- **L2 解放**：回归经营尺度（96 格甚至缩 64 格），军事建筑从"战斗资产"降为"数值+展示资产"

## 五、B 方案落地后的删减/简化清单（院长关心的"删减"）

1. **城墙**：L2 删实体城墙 → 城防=数值（城墙等级字段保留）；战场表现=L3 模板内墙体+耐久参数（等级越高墙越厚/越难破）
2. **defenseTurret/军事基地**：L2 展示件保留或删 → 战场=模板内预设守备点
3. **兵营/兵工厂**：纯功能建筑保留（征募/产线），位置与战斗无关
4. **L3 攻城/野战**：攻城战=城战模板（含城墙）；野战=L1 大地图行军触发→野战模板（按地形类型）——RTK12 会战制原样
5. **L2 尺度**：96×96 格回归"摆得舒服"标准（可缩 64×64），不再追求承载战役

## 六、黑机建议

**选 B（各自为战+参数化战场）**，理由按权重：

1. **架构一致性**：L3 开题 E1~E10 已裁独立战斗 sim——B 是顺着已裁架构走，C 要推翻重裁
2. **L2 解放**：L2 从"战斗承载"重压下解放，回归经营精修——直接回应"L2 不堪"
3. **L3 开发量可控**：模板池 6~10 张+参数注入 ≠ 每城单独开发——院长的初衷被满足
4. **玩家负担**：L2 规划生产、L3 打仗——分工清晰（RTK12/全战双实证）
5. **升级路径**：若未来想做强关联（同格网），数据层已经打通（单向注入→双向同步是增量），表现层再迭代

保留意见（C 方案的合理内核）：C 的"布局有意义"体验在 SLG 里确实独特（围城时真实城市布局起作用）——可作为**远期增强**：L3 城战模板的布点参考 L2 实际建筑分布（数据已有），做到"半关联"。
