## 一、定位与边界

### 1.1 事件的两层（2026-11-19 院长口径）

| 层 | 定义 | 例子 | 触发 | 可推算 |
|---|---|---|---|---|
| **剧情事件** | 剧本/教程脚本，固定年月/条件，服务叙事与教学 | 教程关卡 WLT 自立（t2 固定触发） | 剧本 `EventScript` | 否（剧本决定） |
| **普通事件** | 游戏机制下**自然产生、符合玩家预期、可推算**的事件 | 自由沙盒某城自立/起义/外逃；**事件卡** | 规则层状态公式（阈值/概率公开） | 是（条件+概率+效果可估算） |

- **事件卡归普通事件**的社会经济子类——不是剧情事件，不是黑箱随机：条件、概率、效果全部公开，玩家看到城市状态（W/战争/增长）就能预期"什么可能来"。
- 剧情事件走 `ScenarioDefinition.events`（EventScript）；普通事件走规则层（机制阈值/事件卡）。二者共用事件面板与驻城武将汇报，但**数据通道不同**，不混用。
- 王乐添自立：教程关卡=剧情事件（固定 t2）；自由沙盒中某城自立=普通事件（起义机制自然产物）——同一名字，两种通道，按剧本配置。

### 1.2 事件卡的作用（回答"除丰富剧情/触发机制外还有什么用"）

1. **状态可读化**：把 L2 内部状态量（民生/战争/增长）翻译成玩家看得见的局部经济变化（街 +7/商场 −11）——事件名即诊断信号（口红→民生低/战争久），不需要读公式。
2. **短期策略窗口**：改变局部最优（街 vs 商场、消费 vs 积累），诱导 5~20 回合的经营调整（建造顺序/对冲政策/等窗口过）；没有波动，经济最优解永远一套。
3. **给对冲工具创造需求**：政策卡（消费刺激/紧缩/社保）、科技、建筑选择需要"值得对冲的场景"；事件卡是政策卡的主要使用场景之一。
4. **机制自动调节**：口红=低民生/战争期缓冲阀；报复性=战后恢复加速器；低欲望=高福利后期挑战（防无脑堆福利）。三张卡是主系统的反作用力。
5. **叙事沉浸**（次要）：专有名词带来历史/社会联想，但不作为存在理由。

### 1.3 三张卡的存在检验

| 卡 | 服务的机制目的 | 去掉它少什么 |
|---|---|---|
| 口红效应 | 低民生/战争期的**缓冲阀**（结构转向小确幸，净商业略降但不崩） | 战争期商业只有线性下滑，无结构变化与缓冲 |
| 报复性消费 | 战后恢复的**正反馈奖励** | 战后无加速回暖窗口，恢复纯线性 |
| 低欲望社会 | 高福利后期的**富足陷阱挑战** | 后期福利/消费无制衡，一路堆福利无代价 |

> 设计纪律：每张事件卡必须能回答"服务哪个机制目的，去掉它哪个系统少一个场景"；答不出的卡不进池（不做纯风味事件卡）。

### 1.4 一期范围

- ✅ 3 张商业卡落库（数据+引擎掷骰/冷却/持续/恢复）；机制事件与剧本事件保持现状不动。
- ✅ 事件卡与政策卡/消费池/民生/税收的落点打通（只加乘区，不改基础公式）。
- ❌ 不回溯补卡（院长 #2）；农业/工业/人口/军事/外交/文化候选卡不做。
- ❌ 天灾/异族不进卡池、不在一期实装；本专题只留接口字段（§十）。

### 1.5 与政策卡的边界

| 维度 | 事件卡 | 政策卡 |
|---|---|---|
| 来源 | 外部冲击（历史/社会现象） | 玩家/AI 主动国策 |
| 时长 | 5/10/20 回合，到期自动恢复 | 装卡期间持续，可换卡（冷却内 100 财） |
| 操作 | 不可装/卸 | 五槽 2/2/2/2/2，装卡免费 |
| 叠乘 | 事件乘区与政策乘区**同乘区相乘**（先政策后事件或反之结果同） | 同左 |
| 对冲 | — | 消费刺激/紧缩/社保等政策可抵消事件效果 |

## 二、类型体系（统一 EventDefinition，不新增解释器）

> 四通道定义见 §1.1；本节只定**数据落点**：事件卡 = `type:"general"` + `card` 子对象，剧情事件 = EventScript，机制事件 = 规则层。

**推荐方案**：`type` 枚举保持 `historical|general|achievement|tutorial` 不动；事件卡 = `type:"general"` + **`card` 子对象**（存在即事件卡）。理由：只加字段不改枚举，旧档/旧事件零迁移，符合"新内容=加数据"。

```jsonc
{
  "id": "lipstick_effect",
  "type": "general",            // 枚举不动
  "card": {                     // ← 事件卡标记（唯一新增块）
    "class": "major",           // 与王乐添自立同级；同面板同优先级
    "cooldown": 40,             // 同卡冷却（回合）
    "duration": 5,              // 持续回合
    "triggerChance": 0.20,      // 条件满足时每回掷骰
    "globalMax": 1              // 全局同时最多 1 张卡
  },
  "trigger": { ... },           // §三
  "effects": { "instant": [], "ongoing": [] },  // §四
  "display": { ... },           // §五 卡面
  "report": "本城居民转向小确幸消费"
}
```

- 备选方案 B：新增 `type:"card"`——不采用（动枚举=动解释器分支，违背只加字段）。
- `priority`：事件面板展示顺序用；建议 **剧本事件 100 > 唯一事件 90 > 事件卡 50 > 机制事件 30**（同回合多事件按此排序，不弹窗）。
- `once`：事件卡一律 `once:false`（可重复），王乐添自立 `once:true`。

## 三、触发系统

### 3.1 触发条件（DSL，全部 AND；`trigger.any[]` 内为 OR）

| 字段 | 含义 | 示例 |
|---|---|---|
| `turn` / `turnRange` | 回合/回合区间 | `{"turnRange":[121,999]}`（低欲望 t>120） |
| `cityTag` | 限定城市标签 | `coastal`/`inland`（天灾二期） |
| `welfareBelow` / `welfareAbove` | 民生阈值 | `welfareBelow:35`（口红）、`welfareAbove:70`（低欲望） |
| `warTurns` | 阵营处于战争 ≥N 回合 | `warTurns:5`（口红） |
| `postWarTurns` | 停战/解封后 ≤N 回合 | `postWarTurns:3`（报复性） |
| `growthStall` | 人口/收入连续 N 回合 <X% | `{"turns":10,"rate":0.01}`（低欲望） |
| `loyaltyBelow` | 城市忠诚阈值 | 二期候选卡用 |
| `buildingCount` | 指定类型建筑数 ≥N | 二期候选卡用 |
| `techCompleted` | 已研节点 | 二期候选卡用 |
| `goldBelow` | 国库低于阈值 | 二期候选卡用 |
| `flag` | 剧本旗标（事件链用） | 剧本事件用 |

- 条件必须**明确可读**（民生/战争/忠诚/人口/科技/建筑），禁止"每回合随机 1%"。
- 条件不满足 → 不掷骰；条件满足 → 每回合按 `triggerChance` 掷骰；**同一回合只掷一次**。
- **触发粒度（待裁 #1）**：建议**全局每回合至多 1 次判定**——收集所有满足条件的城市，随机选 1 城作为判定对象再掷骰（防 14 城 ×20% 刷屏）；命中即在该城触发。备选：逐城独立掷骰（频率过高，不推荐）。

### 3.2 冷却与唯一性

```
全局同时最多 1 张卡（card.globalMax=1）
同卡冷却：按卡配置（card.cooldown，视卡强度/频率而定；当前 口红40/报复性50/低欲望60，可调）
两张卡之间全局至少 10 回合（保留；事件卡少，后续细讲）
200 回合内同类卡 1~3 次（验收口径，非硬编码）
```

- **冷却不设统一区间硬约束**（2026-11-19 院长："冷却视情况而定"）——每张卡按机制目的与强度单独配置 `card.cooldown`；新增卡时逐卡标定，不做 40~60 一刀切。
- 同卡冷却期内不再判定该卡；其他卡可判定（但受全局 1 张限制）。
- 冷却/生效状态入存档（§七），读档恢复，不从零重算。

### 3.3 时点：过回合时出现，下回合开始结算（2026-11-19 院长令）

```
回合结束阶段（过回合时）：条件判定+掷骰 → 命中则"出现"事件（事件条+驻城武将汇报，玩家可见）
下回合开始阶段：正式结算（instant 生效、ongoing 开始计时）→ 持续回合从结算回合起算
```

- **出现 ≠ 结算**：过回合过程中不结算任何事件效果；玩家在本回合内看到事件出现，但数值不变。
- 明牌：事件**出现即公开**（事件面板/汇报），不做暗判；机制事件（起义/天灾）的风险提示仍在各自面板常驻，不依赖本流程。
- 存档：需保存"已出现未结算"状态（`pending`），读档后下回合初继续结算（§七）。
- 旧稿"命中→预警→次回生效"表述作废——**不是预警，是出现与结算分离**。

### 3.4 随机性与存档

- 种子存档：同 seed 同开局结果可复现；读档重掷（金手指，已知且接受）；同一回合不重复掷。
- 掷骰记录 `lastRollTurn` 入档，防读档刷同一回合。
- **出现未结算**（过回合时出现、下回合才结算）必须入档：`pendingEvents[]`，读档后下回合初继续结算（§七）。

## 四、效果与落点（主公式）

### 4.1 两类效果

| 类型 | 何时结算 | 用途 | 到期 |
|---|---|---|---|
| `instant` | 生效回合一次性 | 民生冲击/一次性财/人口 | 不返还 |
| `ongoing` | 持续期内每回合 | 建筑回收乘区/池乘区/税收乘区/民生目标偏置 | 自动恢复 |

### 4.2 效果字段 → 主公式落点（每个字段必须找到位置，BUG-G014）

| 字段 | 作用对象 | 主公式落点 | 单位 | 封顶 |
|---|---|---|---|---|
| `streetRecoveryMult` | 商业街回收 | `商业街回收 = min(零售份额剩余,12)×在岗率` **结果再乘**（示例口径：36→43 为 36×1.2，非改单座上限） | 倍率 | ±50% |
| `mallRecoveryMult` | 商场回收 | `商场回收 = min(零售份额剩余,60)×在岗率` **结果再乘**（114×0.9≈103，与示例一致） | 倍率 | ±50% |
| `entRecoveryMult` | 娱乐类回收（文化区娱乐+红灯区） | 娱乐 25% 份额内回收结果再乘 | 倍率 | ±50% |
| `tourismRecoveryMult` | 文旅类回收 | 文旅份额内回收×热度后再乘 | 倍率 | ±50% |
| `consumptionPoolMult` | 消费池上限 | `有效需求 = 民用人口/1000×2.5×K_desire × 事件乘区`（**不改 2.5/K_desire 基础公式**） | 倍率 | ±50% |
| `welfareBias` | 民生目标值 | L2 民生目标 +N（持续期） | 点 | ±5 |
| `welfareInstant` | 民生冲击 | L3 民生一次性 ±N（走冲击通道） | 点 | ±10 |
| `securityBias` | 治安目标值 | L2 治安目标 +N（持续期） | 点 | ±5 |
| `taxMult` | 人口税/建筑财 | `财富 = (建筑财 + 税项) × 税收乘区` 再乘 | 倍率 | ±30% |

- **禁止虚空产出**：字段只能乘/偏置已有量，不新增资源；没有落点的效果一律不进卡。
- **叠加**：同名不叠加（取新触发覆盖旧）；不同名可叠；同城同类总倍率封顶 **±50%**（街/商场/娱乐/文旅/池分别封顶）；民生/治安偏置累计封顶 ±5。
- **与政策乘区**：同乘区相乘；总额封顶各自独立计算，不合并成新上限。
- **显示**：`Δ = 当前值 × (倍率 − 1)`，按触发城当前值结算（§五）。

> 数值=11-02 院长 #1/#2/#5 已批默认值（总表"以此默认值先用着，出现模拟盘问题再调"）；**冷却以本表为准**（民生文档 §一 "20 回合冷却"作废，§二 40/50/60 为准）。

**60k 城示例（3 街+2 商场，池 150）**

| 卡 | 卡面主数字 |
|---|---|
| 口红效应 | 街 +7 财/回（36→43）；商场 −11 财/回（114→103）；净 −4 财/回；税收不变 |

| 低欲望社会 | 消费池 150→135（−15）；娱乐/共享 +10%；民生 +1 |

> 低欲望"文化/共享 ×1.10"落点=娱乐类回收（含共享经济建筑，按文化区娱乐 25% 份额）；民生 +1 建议按 `welfareInstant` 一次性（待裁 #2）。

### 5.1 卡面数值展示（院长 #2 + 11-19 口径）

- **只显示变化项**（2026-11-19 院长令）：卡面只列本次事件产生变化的行；无变化的财/民生/治安/税收/人口行**不显示**（旧"无变化写不变"作废）。
- 主数字=当前城实际 ±（财/回、民生、治安、税收），百分比只做副标题（`+20%`）。
- 打开时按**触发城当前值**结算，不写死全局数字；无对应建筑显示"本城无商场，无此项"（不显示该行）。
- 多城：按城逐个结算/展示；国家报表只给合计。
- 人口行仅在事件改人口时显示（一期 3 张卡均不改人口→不显示）。

## 六、频率与卡池

- 一期限定卡池 **3 张**（总表 §五"暂不回溯"）；二期补卡只加 `events.json` 数据，不改规则。
- 全局同时最多 1 张卡；同卡冷却**按卡配置**（当前 40/50/60，视情况而定）；两张卡之间全局至少 10 回合（保留，后续细讲）；200 回合内同类 1~3 次。
- 条件+概率双闸：条件不满足不掷骰；满足后也不稳定触发（防"条件满足即送收益"）。
- 天灾/异族**不是卡**（低频压力事件，二期）；起义/自立/外逃是机制事件，不占卡池。

## 七、数据 schema 与存档

### 7.1 events.json（事件卡条目）

```jsonc
{
  "id": "lipstick_effect",
  "type": "general",
  "card": { "class": "major", "cooldown": 40, "duration": 5, "triggerChance": 0.20, "globalMax": 1 },
  "trigger": { "any": [ { "welfareBelow": 35 }, { "warTurns": 5 } ] },
  "effects": {
    "ongoing": [ { "streetRecoveryMult": 1.20 }, { "mallRecoveryMult": 0.90 } ]
  },
  "display": { "title": "口红效应", "subtitle": "小确幸消费抬头", "lines": ["street", "mall"] },
  "report": "本城居民转向小确幸消费"
}
```

- 旧 `events.json` 事件零改动；缺 `card` 块=普通事件；未知字段读档保留。
- `display.lines` 控制卡面显示行（无对应建筑自动隐藏）。

### 7.2 存档

```jsonc
"pendingEvents": [
  { "id": "lipstick_effect", "cityId": "beijing", "appearedTurn": 87 }
],
"eventCards": [
  { "id": "lipstick_effect", "cityId": "beijing", "settledTurn": 88, "endsTurn": 93 }
],
"eventCardCooldown": { "lipstick_effect": 48 },
"eventLastCardTurn": 88
```

- **出现与结算分离**：`pendingEvents`=过回合时已出现、下回合初待结算；`eventCards`=已结算生效中（`settledTurn` 起算，`endsTurn` 到期）。
- 旧档无字段 → 无卡、冷却清零；读档恢复 pending（下回合初结算）与生效中卡/冷却。
- 事件卡不阻塞存档/读档（L3 战斗中存档另属存档 v3）。

## 八、UI/面板与汇报

- **统一事件面板**：机制事件/事件卡/剧本事件同一事件流；卡出现=事件条 + 驻城武将汇报，**不弹红窗**（与王乐添自立同级）。
- 事件条单条滚动 + 点击展开日志（L1 战略层开发讨论单 B7）；卡面详情按 §5.1 展示（只列变化项）。
- 生效期：城市面板显示卡图标/剩余回合；HUD 事件条可查。
- 到期：事件条"口红效应结束"提示；数值自动恢复，无需玩家操作。
- 时点：**过回合时出现**（事件条+汇报，数值不变）→ **下回合开始结算**（§3.3）。

## 九、AI 接口（留口，不新增 AI 决策）

- 事件卡对 AI **无选择**：触发后自动吃效果，AI 无需决策（与事件分支无关）。
- 给 AI 的只读接口：
  - `recentEvents[]`（近 N 回合事件/卡记录，含类型/城/开始-结束回合）——供政策 AI 变动因子加权与战争 AI 局势判断。
  - 政策 AI 事件加权（已有口径）：宣战 +0.15/被制裁 +0.20/UN 选举 +0.10/主路径变化 +0.30/强制卡 +0.50；**事件卡出现建议 +0.10**（如低民生口红→消费刺激评估），待裁 §12.2-#4。

- 天灾/异族（二期）对 AI：走各自系统接入（防灾建造/迎战），不在本专题定。

## 十一、验收标准

1. **频率**：200 回合内 3 张卡合计触发 1~3 次/类；全局同时最多 1 张；**同卡冷却按卡配置生效**；两张卡间 ≥10 回合。
2. **随机性**：条件不满足不掷骰；同 seed 可复现；读档重掷可接受；出现未结算入档（pending）。
3. **落点**：每张卡打开后城市实际 ± 与卡面一致（Δ=当前值×(倍率−1)）；**只显示变化项**；到期数值完全恢复。
4. **叠加**：同名不叠加；不同名叠加不超 ±50%（同类）/±5（民生治安）。
5. **存档**：出现未结算/生效中/冷却三种状态读档一致；旧档无字段不崩。
6. **政策对冲**：口红/低欲望期间装"消费刺激"类政策，商业回收按政策×事件连乘，不出现虚空产出。
7. **烟雾**：`events.json` 加一张测试卡（无代码）→ 触发/卡面/结算/恢复/日志正常（代码规范 §四-3）。
8. **不回归**：机制事件（起义/自立/外逃）阈值与结算不变；v22 基线数字不动（事件卡不进 v22，模拟验证挂后续盘）。
