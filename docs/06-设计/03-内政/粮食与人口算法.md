# 粮食与人口算法（B1-F · v4 城级分配制）

> 状态：✅ **v4.0 定稿**（2026-10-30）。**本文件是"粮 ↔ 人口"闭环的唯一权威**。
> **收尾依据**：4 组全量模拟（基线 / 台北自立 / 后期新城 / 全开）零系统性问题；全开场景 200 回合**零饥荒**、人口 663,551。
> v1~v3 的**粮安 F 指标、地力衰退、国家单一大池**全部作废。
> 上游：[农业区数值.md](./农业区数值.md)（Q 的来源）· [人口算法-v1.md](./人口算法-v1.md)（W/忠诚主式）。
> 验证脚本：`tmp/sim-v4.js`（城级分配 + 新城扩张 + AI 互贸，200 回合）。

## 〇、核心原则（一句一条）

1. **本城粮食优先供给本城**。每座城先吃自己产的，有余才上交国家，不够才向国家要。
2. **库存 K 是唯一粮食安全指标**，不再有粮安 F 百分比。
3. **危机 ≠ 饥荒**。库存减少是危机（红箭头），库存为负才是饥荒（死人）。
4. **饥荒按城判断**：有余粮的城永远不饥荒，缺粮城按缺粮量减人口。
5. **不做手动调粮**。不允许玩家"牺牲 A 城把粮全给 B 城"，哪怕历史上真有这种事——这是防操作滥用。
6. **不展示中间量**。牧场耗料、单城净差额的内部计算都在后台，界面只给玩家能决策的数字。

## 一、公式链（七段）

```
① 城级收支  net_i = Q_i − D_i                     // 每城先算自己的
② 国家池    P = Σ max(0, net_i)                   // 余粮上交
③ 分配      缺粮城按人口比例领 P（不超过本城缺口）
④ 库存      K' = K + Σnet_i + 进口 − 出口，上限 8×D_total
⑤ 饥荒      分配后仍缺 → 该城按缺口减人口
⑥ 民生      W 粮项 = 11 − 30×min(缺口率, 1)
⑦ 人口      增长 = Pc × 2% × f_L × f_F × f_C
```

**闭环**：`建居民楼 → C↑ → 人口↑ → D_i↑ → net_i↓ → 国家池不够 → 缺粮城饥荒 → 人口↓`。

## 二、① 城级收支（这是 v4 的地基）

```
Q_i = Σ农田(净产) + Σ牧场(净产) + Σ渔场(48) + Σ食品工业(45)
D_i = Pc_i/1000 + 1.5×A_garrison_i/1000
net_i = Q_i − D_i
```

| 项 | 说明 |
|---|---|
| **Q_i** | 本城所有农业建筑产出之和。**每城必须单独算**——这是第 4 条 UI 的硬前提 |
| **D_i** | 本城平民 + 驻军（驻军 1.5 倍口粮） |
| **net_i > 0** | 本城有余粮，可外调 |
| **net_i < 0** | 本城是缺口，需要外调 |

- **出征部队不在 D_i 里**：出征时一次性带粮（`携粮 = 兵/1000×1.5×预计回合×1.2`），回城返 50%。
- 达尔文独立粮池（`net` 只跟自己比，不参与任何国家池）。

## 三、②③ 国家池与分配（院长第 4、7 条）

```
P        = Σ max(0, net_i)          // 全国余粮（只有正数上交）
G        = Σ max(0, −net_i)         // 全国缺口
缺粮城 i 可得量 = P × (g_i / G)      // 按缺口比例（院长 2026-10-30 定）
分配后缺口 short_i = g_i − 可得量
```

**分配顺序**（严格按此，不可干预）：

1. 每城先吃自己的 `min(Q_i, D_i)`。
2. 有余粮的城，多余部分**全部上交**国家池（本城不留私粮）。
3. 国家池按**缺粮城的缺口比例**分配——缺得多的分得多，一轮到位，不需要两轮。
4. 分配后仍缺 → 动用国家库存 K。
5. K 也耗尽 → 饥荒（§五）。

> **为什么改按缺口比例**：按人口比例效率低（人口多但缺口小的城会先吃饱、把余粮浪费掉）。按缺口比例是"按需分配"，缺多少补多少，一次分配到位。代价是缺粮最严重的城会拿到最多——这恰恰是想要的（先救命）。

## 四、④ 库存 K

```
K' = clamp( K + Σnet_i + 进口 − 出口 , 0, 8×D_total )
```

- **上限 8×D**（院长保留）：占领粮城后敌国有 8 年缓冲，够组织反攻。这是防"几回合饿死一国"的滚雪球。
- **下限 0**：饥荒年的亏空不跨年累积（否则一次大灾永远还不完）。
- 库存的单位是**年份**（K/D），UI 显示"库存 2.9 年"。

## 五、⑤ 饥荒（K < 0 且分配后仍缺）

```
城 i 的缺口率 d_i = short_i / D_i
年死亡 = Pc_i × min(5%, 10%×d_i)
宜居 L −= 15×min(d_i, 1)
民生 W 粮项 = 11 − 30×min(d_i, 1)
```

- **有余粮的城绝不会饥荒**（`net_i ≥ 0` → `short_i = 0`）。
- **缺粮城按缺粮量减人口**，不是按人口比例均摊——缺得多的死得多。
- 死亡是**该城自己的 Pc**，不影响其他城。
- 人口下限 1,000（城不会消失，同达尔文形态）。

## 六、⑥ 民生与人口

```
W 粮项 = 11 − 30×min(d_i, 1)                       // d_i=0 时满额 +11
f_L = clamp(L/60, 0.50, 1.50)
f_F = clamp(0.40 + 0.30×min(m, 2), 0, 1)           // m = K/D 国家库存年数
f_C = clamp((C − P)/C, 0, 1)
增长 = Pc × 2.0% × f_L × f_F × f_C
if d_i > 0: 增长 = −min(5%, 10%×d_i)
```

- `f_F` 用**国家库存**而不是城级——因为生育意愿看的是"国家粮食安全"，不是"我这城有没有余粮"。
- 基础增长率 **保持 2%**：承载闸门（f_C）已经把复利限制住了（见 §九 敏感性表）。

### 7.2 UI 形态

**不写"拖累/贡献"这种价值判断词，只用数字 + 颜色。**

```
城市面板 · 粮食
  北京   余粮 +8     ● 绿
  台北   余粮 +23    ● 绿
  香港   余粮 −28    ● 红
  深圳   余粮 −40    ● 红
  ─────────────────────
  全国   余粮 −14（= 各城之和）  ● 红
```

| 显示 | 颜色 | 含义 |
|---|---|---|
| `余粮 +N` | 绿 | 本城自给有余，粮食外调 |
| `余粮 −N` | 红 | 本城不足，靠其他城补 |
| 全国合计 | 同色 | **= 各城余粮之和**，直接对应国家库存的变化率 |

- **全国合计 = Σ net_i**，这是"本城优先供给本城"原则的自然结果：先各自吃饱，剩下的才是国家的。
- 悬停单城可展开：产出明细（哪块田/哪个牧场贡献多少）、需求（平民/驻军）、耕地余量、渔场余量。
- **牧场只显示净产**（第 2 条）：显示"余粮 +6"，不显示"产肉 45 / 耗饲料 12"。玩家看到的就是一个"低产但给民生"的选择。

## 八、进口 / 出口（院长第 3、6、10 条）

### 8.1 定价

```
卖方可供量  X_s = max(0, Q_s − D_s) × 0.60
买方缺口率  g   = max(0, G_b) / D_b
溢价        m   = clamp( 2.5×g^1.5 + 1.5×max(0, 2−m_s)/2 + (50−rel)/60 , 0, 6 )
成交价      P   = P0 × (1 + m)          // P0 基准价，暂 1 财/粮
```

三道防线（防买空）：只能买当年余粮的 60%、卖方库存不足 2 年要加价、交战方禁贸。

### 8.2 AU 的优势：**本轮不加限制**

- 院长口径：AU 开局对外没有可见度（不知道谁缺粮、谁有余粮），本身就是限制。**先这样**，等实机验收游戏体验后再调。
- 因此 v3 提的"市场深度""价格随量下跌"**暂不实装**，只作为后续备选记在 §十一。

### 8.3 断供（停售）的后果

| 对象 | 后果 |
|---|---|
| 卖方 | 关系 **−20**（一次性） |
| 买方 | **不直接扣任何数值**。买方会在后续回合因为进口中断出现粮食危机 → 民生/人口自然下滑 |

- 关键：**不直接扣 W**。断供的伤害通过"粮食危机"这条真实链路传导，符合"不直接增减"原则。

### 8.4 AI 互贸（第 10 条）

```
触发条件：K/D < 1.5 且 国库 > 300 且 存在可出口国
行为：先找关系最好的余粮国，买 min(缺口, 可出口量)
```

模拟结果（`tmp/sim-v4.js` C 组）：**开启 AI 互贸后，开局那 1 回合轻微饥荒直接归零**，KR/JP/CN 的库存曲线都更平滑。AI 之间会有实际的粮-财流动。

## 九、人口增速分析与余粮用途

### 9.1 敏感性（2% 基础值为什么不改）

| 场景 | P/C | L | m | 实际增长率 | 200 年倍数 |
|---|:--:|:--:|:--:|:--:|:--:|
| 新城 | 0.50 | 60 | 2 | **1.00%/回** | 7.3×（被承载卡住） |
| 一般城 | 0.80 | 60 | 2 | 0.40%/回 | 2.2× |
| 一般城 + 缺粮 | 0.80 | 60 | 0.5 | 0.22%/回 | 1.6× |
| 接近承载 | 0.95 | 60 | 2 | **0.10%/回** | 1.2× |

`f_C` 是唯一能归零的因子，所以"人口快速上升期"= **玩家大量建居民楼的那段时间**，不是年份。压力是扩张的自然结果。

### 9.2 余粮用途（现实 IGC/OECD-FAO 2023）

| 用途 | 全球占比 | 游戏落点 |
|---|:--:|---|
| 食用 | ~43% | 基础口粮（D） |
| **饲料** | **38~45%** | 牧场净产 32~36（低于农田 40），**耗料不展示** |
| 工业加工 | ~16% | 工业区**酿造厂**（粮 30 → 财 25） |
| **生物燃料** | **~7%** | 工业区**生物燃料厂**（粮 40 → 碳 −2） |
| 其他 | ~13% | 种子/损耗 |

- 牧场净产：牛 33（民生 +3）/ 猪 36 / 羊 36 / 鸡 32。**全部低于农田 40**，玩家选它是为了民生和副产，不是为了粮。
- 养猪场同城有玉米或大豆时，净产 36 → 40（饲料成本降，但**界面上只看到 40**）。

### 10.3 后期开 3 座新城（t=100）

| 回合 | 人口 | CN 净差 | CN 库存年 | 新城 |
|:--:|:--:|:--:|:--:|:--:|
| 50 | 444,093 | +59 | 8 | 0 |
| 100 | 525,269 | **+14** | 7.6 | 3 |
| 150 | 587,953 | **−17** | 5.8 | 3 |
| 200 | 659,117 | +47 | **3.2** | 3 |

- **开新城会立刻拉低余粮**：3 座城（各 5k 人）+15 粮需求，但新城没有农业 → 国家净差从 +59 掉到 +14。
- **库存缓冲扛住了**：7.6 → 5.8 → 3.2 年，全程无饥荒。
- **玩家需要给新城配套农业**，否则 3~4 年后库存见底。这是"扩张有代价"的正确表达。
- 结论：**新城扩张的余粮浮动是"渐进下降 + 配套农业后回升"，不是断崖**。

## 十三、施工影响（黑机）

- `CityState`：`FoodProduced`（Q_i）、`FoodDemand`（D_i）、`FoodShort`（分配后缺口）——**这三个字段是 v4 的核心**，围城、城级 UI、饥荒全靠它们。
- `FactionState.FoodK`：可负（饥荒年），上限 8×D。
- `balance.json`：`food.{Kmax:8, initStockYears:3, surplusShareByPopulation:true, famineDeathMax:0.05, famineDeathCoef:0.10, wFoodMax:11, wFoodPenalty:30}`
- 新增建筑：`brewery`、`biofuel`（工业区，科技解锁）
- 牧场：`foodOutput` 与 `foodConsume` 分别存储、UI 只读净产
- 新城：`newCity` 默认 5k 人口 / 8k 承载 / 耕地 2 / 无初始农业
