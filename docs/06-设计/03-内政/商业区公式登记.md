## 二、审计发现（按严重度）

### P0-1 人口税有 4 个版本

| 来源 | 公式/实际 | 60k 城 |
|---|---|---:|
| 工业区 v1.0 | `30 + 人口/1000` | 90 |
| 农业区 v1.1 / 建筑表 | `100 + 人口/1500` | 140 |
| 建筑表 B1-16 建议 | `30 + 人口/2000` | 60 |
| **引擎 `CitySettlement.cs`** | `建筑财 + 50 平税` × 乘区 | **50 + 建筑财（无人口项）** |

**处置**：院长已裁 **`60 + 1.5×民用人口/1000` + 商业维护 3%**（人口税与土地价格 §二）；代码在 `baseTaxPerCity` 基础上加人口项；外籍占领 ×0.5，收复 ×1.0。

### P0-2 初始人口 119k vs 398k

| 来源 | 总人口 |
|---|---:|
| `cities.json` / 人口数值表 R49 | **398k** |
| 工业区 v1.0 模拟 | **119k** |
| 商业区 v7 模拟 | **119k** |

**处置**：`cities.json` 是实际游戏数据，v8 必须用 **398k**；v7 的 837k/676k 锚点不可直接比较。需在 v8 报告里双跑 119k/398k 对照。**这是模拟结论可信度的前置问题。**

### P0-3 民生乘区 vs “民生不直接影响消费”

- `数值公式总纲 §4.1` 的产出公式有 `×(0.8 + 0.4×W/100)`，对**所有产出**生效；代码 `CalcOutputs` 也乘 `WelfareBase + WelfareScale×W/100`。
- 院长 #7：民生**不直接作为消费力因子**，只通过耦合间接影响。
- **处置**：**消费回收（街/商场）不吃民生乘区**；写字楼/工业/农业产出仍吃（生产力耦合）。需在代码里把“消费回收”与“生产产出”分开；文档 C-02/C-03 加注。

### P0-4 贸易货物模型 vs 财流模型

- 旧稿 `贸易最小规则 v0.1` 有粮/铁/煤/铀/装备货物、价格、断供；院长 #3 明确“民间贸易只有财”。
- **处置**：已重写为 v0.2 财流版；删除货物/价格/断供；粮/铁/煤只走国内产需。**旧稿公式作废，留档备查。**

### P1-1 维护费口径

- 文档：维护=财造价×1%；`balance.json`：`maintenancePerBuilding=10`（旧字段）+ `def.Maintenance` per building。
- **处置**：以 `def.Maintenance` 为准；`maintenancePerBuilding` 标记 legacy，不参与结算；商业建筑补维护列（1/2/3/3/3）。

### P1-2 消费池“人口” vs “民用人口”

- 旧稿多处写 `人口/1000`；现已统一 `民用人口=总人口−服役`。
- **处置**：C-01/W-01 已改；全库 grep 旧“池=人口/1000”待清（商业区开题/消费力专题已清）。

### P1-3 商场单座上限

- 旧稿 `min(池, 人口/1000×2)` → 模拟发现恒 1.25 座饱和；已改固定 60。
- **处置**：C-03 已改；全库 grep 旧式待清。

### P1-4 回收 ×在岗率

- 旧稿街/商场回收未乘在岗率；现已加。
- **处置**：C-02/C-03 已加；写字楼原本有；银行乘数在 ×在岗率之后乘（顺序：池上限→在岗率→银行）。
