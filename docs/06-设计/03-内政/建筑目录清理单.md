## 一、清理四态（每个 ID 必落一态）

| 态 | 含义 | 动作 |
|---|---|---|
| **保留** | 现行有效、有数值有产出、在权威目录内 | 不动 |
| **合并** | legacy/重复 ID，语义已被新 ID 取代 | 写**别名映射** `old → new`，保留一个版本过渡后删除 |
| **删除** | 无对应设计、无引用 | 直接删（先全库 grep 引用） |
| **翻 status** | draft 但有设计意图 | 统一 `status:"draft"` + 补 `role/tags`；无输出字段的标 `outputs:[]` 并在 AI 需求池排除 |

## 二、目标目录口径

以 [建筑数值表](./建筑数值表.md) §一 的 12 类 47 种为准（居民区 8 / 农业 5 作物+4 牧场+渔场+食品工业 / 工业 18 / 商业 / 学院 / 娱乐 6 线 / 文旅 / 公共文化 / 市政 / 军事 / 城墙 / 铁匠）。**目录外的 ID 一律进"合并/删除/翻 status"**，不允许"无归属常驻"。

## 六、验收

| 项 | 标准 |
|---|---|
| ID 唯一 | `buildings.json` 无重复 ID（脚本查重） |
| 无归属 | 每个 ID 在权威目录或标注"内容未定稿" |

## 七、风险

- **删 ID 破坏旧档** → 别名映射 + 未知 ID 跳过，过渡一个版本
- **draft 翻 status 后误入结算** → `status:"draft"` 不参与结算（既有铁律）
- **数值 ×8 未同步** → 清理时顺带核对 v22 注记，避免"清理完还得再改一轮"
