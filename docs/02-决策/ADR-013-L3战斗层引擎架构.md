# ADR-013 · L3 战斗层引擎架构（E1~E10）

> 状态：✅ 已接受（2026-11-23 院长逐条裁定）
> 关联：[L3战斗层开题 v0.3](../06-设计/04-军事/L3战斗层开题.md) · [L3引擎层裁点材料](../06-设计/04-军事/L3引擎层裁点材料.md) · [RTS引擎实现调研](../00-调研/RTS引擎实现调研.md) · [RTS战斗层设计调研](../00-调研/RTS战斗层设计调研.md) · [索引-决策](../06-设计/00-总纲/索引-决策.md)
> 基准：玩家机 **RTX 4060 + 16GB 内存**，1080p 60fps；一个部队=一个逻辑单位，下辖 1~几十万士兵。

## 背景

L3 战斗层进入开发，需要一次性定下仿真路线、逻辑帧率、回放、倍速、寻路、群渲、broad-phase、性能、迷雾、AI 十项引擎层架构。约束：
- 确定性（同 seed 可复盘/观战）与可调试性优先；
- 几十万士兵不能按 1:1 逻辑单位处理；
- 单机离线、4060 中端卡、16GB 内存；
- 建筑是可攻击/可进入/可掠夺的战场实体；
- 后续可平滑扩展，不因早期技术选型推倒重来。

## 决策

1. **E1 仿真路线**：纯 C# 轻量仿真层（Mono + 自管 ITick），Sim 域无 UnityEngine 依赖；一期不开 DOTS。二期触发=士兵个体化逻辑 5000+。
2. **E2 逻辑帧率**：渲染 60fps + 逻辑 **30Hz**（`balance.l3.tickHz`）；输入每渲染帧采样、下一 tick 执行；**游玩固定 1x，倍速仅观战**。
3. **E3 回放**：命令流（tick+指令）+ 种子 + 场景版本号；只要求"观战看过程"，不做深度复盘/统计/跨版本；同版本可复盘；可选轻量状态哈希。
4. **E4 倍速/暂停**：每渲染帧多跑 N 个 sim tick；**不碰 timeScale**；观战三功能=正常/加速/跳过；**跳过=无渲染跑同一套 sim**；暂停停 tick、渲染照常插值。
5. **E5 寻路**：部队锚点网格 A*（L2 96×96 同构）+ 士兵零寻路；普通建筑**软代价、可进入**；带碰撞建筑硬挡；城墙摧毁后只更新受损段网格。
6. **E6 群渲**：GPU 人群渲染 + LOD/Impostor + **表现比例**；兵力数字 ≠ 表现人数，**不 1:1 全画**；高画质视觉预算 6000 低模 + 50000 面片；方阵占地 ∝ √兵力；损耗递减模型数。
7. **E7 broad-phase**：均匀 spatial hash 只服务部队/投射物/建筑目标；表现层独立处理可见士兵碰撞；impostor 不碰撞。
8. **E8 分帧/Burst**：逻辑主线程 1~2ms；**表现层第一天就 SoA/NativeArray/实例缓冲**；Burst/Jobs 后置但不改架构；帧预算 CPU≤8ms/GPU≤14ms。
9. **E9 战争迷雾**：sim `byte[W×H]` 三态数组 + 视野计数器增量 + 双 RT + 可分离模糊；AI 只读 sim，绝不读渲染产物；按部队/建筑算，不逐兵。
10. **E10 AI 战术层**：三层（utility 战略 + TPS/影响力图战术 + FSM/BT 单位）+ **Petra 隔离**（AI 只产出命令）；ML/RL 二期可选，不进 M1~M4 关键路径。

**配套交互/表现裁定**（同日院长）：
- 敌方军事/城墙可攻击；城墙摧毁后通行；军事基地血量归零转普通建筑（可进入/掠夺，掠夺 ×2 爆产出）。
- 敌方普通建筑可直接进入/掠夺；敌方建筑被摧毁或攻占后可进入；驻守/掠夺右键菜单。
- 掠夺持续引导 Lv1/2/3=8/12/16s；受击/手动打断；重掠夺从 0 引导。
- 光标状态机：红剑=攻击/门=进入/金币=掠夺/空地=移动/禁止=不可操作；优先级 Attack>Enter/Plunder/Garrison>Select>Move。
- LOD 默认中景、鼠标滚轮缩放、16/5px 初值（待地图/UI 后调）；质量档高/中/低/极低自动降档保 60fps。

## 否决方案（存档）

| 方案 | 否决理由 |
|---|---|
| 一期上 DOTS/ECS | 30 部队+3000 表现士兵用不着；Subscene/Baking/调试门槛高；Sim 域纯 C# 保留迁移保险 |
| 60Hz 逻辑 | 画面是插值出来的，逻辑 60Hz 无额外视觉收益；观战加速 tick 数翻倍、确定性面更大 |
| 快照主回放 | 体积大，与"缩略加速"冲突；命令流为五款 RTS 同构做法 |
| timeScale 做倍速 | 污染协程/物理/动画，暂停语义不符；只留慢镜头演出 |
| 逐士兵寻路/NavMeshAgent | 请求数 O(士兵) 爆炸；NavMesh 动态更新差；城市权重图用网格 A* |
| JPS 主寻路 | 仅 uniform-cost 网格适用，权重地图失效；30 请求量用不着 |
| 逐士兵 SkinnedMesh+Animator | ~50 个即瓶颈；SkinnedMeshRenderer 不支持 GPU instancing |
| DrawMeshInstanced 主方案 | 1023/次硬上限；只能兜底 |
| 四叉树 broad-phase | 均匀密集移动对象不划算；spatial hash 更简单 |
| CPU 高分辨率迷雾 | 每帧纹理上传/计算成本高；双 RT+可分离模糊是工程标准 |
| 纯 BT/GOAP/RL 做基础 AI | BT 不擅长持续权衡；GOAP 对固定战场过度；RL 训练/调试/可控性不适合单机一期 |

## 后果

- **正面**：确定性/可复盘；逻辑与表现解耦，几十万士兵可表现而不爆 CPU；建筑/掠夺/驻守有统一实体基础；4060 有明确预算目标。
- **代价/风险**：E6 美术烘焙管线 lead time 最长（M1 期先做单兵种验证）；4060 压测未做（6k 低模/50k 面片/30 方阵）；LOD 阈值/视觉预算/掠夺数值均为初值可调；ML/RL 留二期实验。
- **数据待落**：`buildings.json` 增 `attackable/enterable/plunderable/blocksMovement/capturable/destructible/fadeWhenOccupied`；`balance.l3` 落 30Hz/掠夺/视觉预算/LOD 参数。

## 核验

- M1：BattleSimManager+30Hz tick+命令流+同 seed 两跑哈希一致；4060 压测三档。
- M2/M3：战斗解对齐 sim B1 ≤10%；城墙摧毁/军事基地转普通建筑/掠夺打断/驻守。
- M6：光标/右键菜单/LOD 降档实机目检。
